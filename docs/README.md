# GOSU 문서 안내

[0.58.151 설치](releases/0.58.151.md): 연구 노트 접근이 다시 된다. 0.58.147이 볼트 식별자를 바꾸고 저장된 식별자를 옮기지 않아 모든 프로젝트가 다른 볼트로 보였다. 같은 프로젝트를 주장하는 폴더가 둘이면 추측하지 않고 멈춘다.

[0.58.149 설치](releases/0.58.149.md): 논문에 대해 AI와 나눈 질의응답이 그 논문에 기록된다. 논문 요약에서 AI 대화 아이콘과 AI 질의응답 필터로 찾을 수 있고, 다른 검색 조건과 함께 쓴다.

[0.58.148 설치](releases/0.58.148.md): AI 대화를 열 때 나오는 추천 질문을 설정 → Agent에서 끌 수 있다. 논문에 대한 질문은 설정한 논문 요약 AI 모델로 실행한다.

[0.58.147 설치](releases/0.58.147.md): 연구노트 허용이 앱 업데이트 뒤에도 남는다. 폴더 이름을 경로만으로 정하게 고쳤다. 사용량은 Codex 계정 하나를 한 줄로 보여주고, 격언은 이력에 없던 주제를 고른다.

[0.58.146 설치](releases/0.58.146.md): Briefing Lab 스크롤이 간헐적으로 멈추던 문제를 고쳤다. 원인은 그리기 성능이 아니라 이력 화면이 보관된 브리핑을 전부 한 번에 그리는 구조였다.
브리핑 30개일 때 이 화면이 한 번 다시 그려지는 데 394밀리초, 60개면 857밀리초가 들었고, 브리핑이 끝나거나 지침이 들어오거나 읽음 처리를 할 때마다 그만큼 화면이 멈췄다.
이제 최신 브리핑 8개만 그리고, 아래로 내려가면 8개씩 이어서 불러온다(버튼도 있다). 같은 조건에서 113밀리초와 167밀리초로 줄었고, 보관된 이력이 많아도 더 느려지지 않는다.
알림으로 특정 브리핑을 열면 그 브리핑이 목록 아래쪽에 있어도 반드시 그려진다.
같은 설치본에 다른 작업 두 가지가 함께 들어갔다. 설정의 SSH 연결 카드에서 서버마다 "AI가 기억할 메모"를 적을 수 있고(공용 장비에서 쓸 계정 같은 것),
그 메모는 Project Chat의 AI가 그 서버를 다룰 때 함께 읽는다. 연결 정보와 따로 저장하므로 메모를 고쳐도 그 서버에 준 접근 승인이 취소되지 않는다.
그리고 문헌 화면의 BibTeX 내보내기가 DOI와 링크 주소를 있는 그대로 쓴다. 전에는 `10.1007/978-3-030-58452-8_13` 같은 밑줄이 `\_`로 나가서 LaTeX에서 링크가 깨졌다.
예전 GOSU가 내보낸 파일도 그대로 다시 읽어 들인다.

[0.58.145 설치](releases/0.58.145.md): 제목 표시줄 오른쪽의 "로컬 · 동기화 대기"를 없애고, 그 자리에 지금 돌아가는 AI 작업을 한 줄로 설명한다. 여러 건이면 1.5초마다
번갈아 보여 주고, 작업 중에는 사이드바와 같은 별이 돌며 끝나면 노란 별로 바뀐다. 클릭하면 그 작업을 하는 화면으로 바로 이동하고 확인 표시도 함께 된다. 아무 작업이
없으면 아무것도 보이지 않는다. 동기화 대기 건수는 설정의 연결 화면 "Sync API" 줄로 옮겼다. 오늘의 격언은 연구 이야기에만 머물지 않는다: 일상·시간·돈·습관·가족·사랑·
음식·잠·여행·실패·나이 듦 같은 주제를 날짜별로 번갈아 제안하고, 연구와 마감은 사흘에 하루 이하로만 나온다. 내장 격언에도 삶에 대한 문장을 언어마다 아홉 개씩 더했다.
왼쪽 사이드바는 굵은 글씨를 모두 없앴고, 프로젝트와 그 하위 항목은 상위 제목보다 한 단계 작게 읽힌다.

[0.58.144 설치](releases/0.58.144.md): 제목 표시줄의 오늘의 격언 옆에 새로고침 단추를 넣었다. 누르면 같은 모델(설정 → Agent의 "가벼운 작업")이 새 격언을 쓰고,
쓰는 동안에는 GOSU의 다른 AI 작업과 같은 별 표시가 돈다. 하루 열 개까지이며 열한 번째로 누르면 모델에 묻지 않고 격언 자리에 "오늘 격언은 여기까지. 나머지는 실천의
몫입니다."가 잠시 뜬 뒤 원래 격언으로 돌아온다. 실패한 시도도 열 번 중 하나를 쓴다. 격언을 클릭하면 지금까지 쓰인 격언을 생성 시각과 함께 볼 수 있다(최대 200개 보관).
사용량 화면의 token 추세 막대에서 빗금을 없앴다. 거의 모든 날이 빗금이라 구분이 되지 않았기 때문이며, 같은 사실은 그래프 아래 문장과 각 막대의 설명, Token 데이터 표의
집계 범위 열에 그대로 남아 있다.

[0.58.143 설치](releases/0.58.143.md): 모든 AI 채팅(Project Chat, AI 비서, Model Lab의 Model Assistant)에 `/new`와 `/compact`를 넣었다.
메시지가 명령 하나뿐일 때만 명령으로 처리하며("/compact 이 문단 줄여줘"는 그대로 질문), 명령은 모델로 보내지도 대화에 저장하지도 않는다. `/compact`는
문맥이 찰 때까지 기다리던 기존 요약을 지금 실행한다: 최근 메시지 4개만 원문으로 남기고 나머지를 요약으로 바꾸며, 이미 요약된 부분은 다시 요약하지 않고 대화
기록은 지우지 않는다. `/new`는 AI 비서와 Model Assistant에서 문맥 시작점을 옮기고 화면에 "여기부터 새 대화" 구분선을 그리며, 위 메시지는 화면에만 남는다.
Project Chat에서는 기존 "＋ 새 채팅"과 같다. 입력창에 "/"를 치면 명령 메뉴가 뜨고, 반쯤 친 명령은 Enter로 완성된다. 답변 중에는 두 명령을 거절하고 이유를
알린다. Project Chat의 `/compact` 실패는 원인별 문장으로 알린다(문맥 크기 미확인, 지원하지 않는 제공자, 설정 변경, 요약 오류, 모델 호출 실패, 중단).
문맥 표시기 상세 창에도 두 명령 안내를 넣었다.

[0.58.141 설치](releases/0.58.141.md): 프로젝트 문헌 검색을 고쳤다. 검색어의 주제어를 논문 자체가 언급해야만 저장하고(순위 정책 버전 4),
무관한 논문으로 50편을 채우지 않는다. Semantic Scholar의 첫 요청은 요청 한도·시간 초과·오류에 세 번까지 다시 시도하며, 빠지면 이유를 한국어로 알린다.
문장이나 한국어로 입력하면 AI가 영어 키워드 검색어 1~3개로 바꿔 차례로 검색하고 실제 검색어를 보여 준다. "논문 검색"처럼 주제가 없는 입력은 거절한다.
검색 뒤 AI 정리는 이번 검색으로 새로 생긴 논문만 10편씩 읽고, 실패 이유를 시간 초과·모델 실패·시작 실패로 구분한다. 알림에 "추가된 N편 되돌리기"가 생겼다.
Project Chat은 일상적인 표현("관련 논문 찾아줄래?", "논문 검색")에도 문헌 검색 도구를 받고, 못 받은 턴에는 어떻게 요청하면 되는지 안내한다. 검색 결과의 논문
링크(DOI·arXiv)를 답변에 쓰도록 했다. 논문 요약 보관함 카드는 확인 가능한 링크만 제안하고 논문마다 따로 저장하며, 링크가 없으면 필요한 링크를 알려 준다.
논문 요약에 BibTeX 내보내기, 문헌 화면에 "논문 요약에서 불러오기"를 넣었다. 사이드바의 "프로젝트"·"아카이브" 머리줄을 다른 행과 같은 열·글자 크기로 맞췄고,
알림 창의 "모두 읽음"을 눈에 띄는 버튼으로 바꿨다.

[0.58.140 설치](releases/0.58.140.md): 브리핑마다 이메일 제목 옆에 "모두 읽음 (N)" 버튼을 넣었다(요청 한 번, 확인도 한 번, Mail에는 기존의 검증된
한 통 단위 쓰기로 차례로 반영, 실패한 메일은 이유와 함께 남음). AI 비서의 메일 검색은 더 이상 브리핑 조회 기간으로 잘리지 않는다: 저장된 일수는 브리핑을 만들 때와
`from` 없는 검색의 기본값일 뿐이고, 더 이전 날짜를 주면 그대로 찾는다. 기간이 넓은 검색은 Mail 색인에서 보낸 사람·제목 단어로 먼저 좁혀 빠르게 찾으며, 색인을 못
읽으면(전체 디스크 접근 권한 없음) 메일함 전체를 훑는 대신 필요한 조치를 알린다. 사용량 화면은 "모델별 사용량" 카드를 없애고 사용 분포의 모델 막대를 입력·출력
색으로 나눴으며, 맨 아래 탭에 Briefing과 논문 요약(날짜·모델별)을 더했다. 논문 요약 사용량은 이 버전부터 `paper_summary`로 따로 기록한다.
프로젝트 문헌 검색 문제는 원인만 조사해 기록했다.

[0.58.139 설치](releases/0.58.139.md): AI 비서와 Project Chat에서 문맥 사용량 칩을 눌러도 상세가 보이지 않던 문제를 고쳤다. 상세 패널이 호스트마다 다른
부모 상자를 기준으로 한 절대 위치였고 그 상자들이 넘치는 내용을 잘라 냈다(AI 비서는 입력 상자, Project Chat은 채팅 전체 상자 위쪽). 이제 브라우저 top layer의
popover로 열리고 칩의 화면 위치에서 자리를 잡는다. 사용량 화면의 "사용 분포"는 기능마다 막대를 모델별 구간으로 나누고 그 아래에 모델 이름과 비중을 적는다(모델
목록의 색 점이 범례). Briefing Lab 이력에는 "안 읽은 메일만" 버튼을 넣었다: 저장된 읽음 상태만으로 거르는 표시 필터이며 Mail을 다시 조회하지 않고, 상태를 모르는
메일은 숨긴 수를 알린다.

[0.58.138 설치](releases/0.58.138.md): 사용량 화면에 기능별 API 환산 비용과 "사용 분포"(모델별·기능별 순위 막대)를 더했다.
기능에는 단가가 없으므로 기능의 금액은 그 기능을 실행한 모델별 금액의 합이다. 이를 위해 리포트에 "기능 × 모델" 집계 `byWorkloadModel`을 더했다(AI 비서·브리핑
요약처럼 프로젝트가 없는 행도 포함). 화면의 모든 금액(요약 카드, 모델 카드, 두 목록, 기능 표)을 이 집계 하나에서 계산하므로 기능 합계 = 모델 합계 = 카드
합계가 정확히 맞는다(묶는 방식이 다르면 캐시 수가 사라져 합이 어긋난다). "사용 분포"는 모델과 기능을 큰 순서로 나열하고 줄마다 토큰과 금액을 함께 보이며,
"토큰 | API 환산" 전환은 정렬과 막대만 바꾼다(기본은 비용). 가격을 모르면 0이 아니라 "가격 미확인"·"—"·"모델별 내역 없음"으로 표시하고, 가격표가 없으면 비용
표시는 전혀 나오지 않는다. 일별 추이의 비용 보기는 넣지 않았다(일 × 모델 집계가 필요하며 평균 단가로 추정하지 않는다).

[0.58.137 설치](releases/0.58.137.md): 요약에 실패한 메일도 제목·보낸 사람·받은 시각은 브리핑에 남김, 새 브리핑 단축키를 설정에서 변경, 전체 디스크 접근 권한 안내와 최초 실행 권한 도우미, 라이브러리 질문에 "추가"/"나중에" 버튼.
(1) AI 요약이 실패한 메일(묶음 실패, 검증 실패, 로그인·모델 문제로 실행이 멈춘 경우)을 요약 없이 기록한다. 저장소는 빈 요약을 "아직 요약되지 않음"으로
취급하므로 다음 브리핑에서 다시 요약하고, 같은 날이면 그 요약이 빈 항목을 대체한다. 인증 코드 메일과 사용자가 중단한 실행은 남기지 않는다.
(2) ⇧⌘Enter(새 브리핑 실행)는 설정 → 단축키의 네 번째 항목이다: 바꾸거나 끌 수 있고 다른 단축키와 겹칠 수 없다. 메인 프로세스가 키를 가로채므로 포커스와
