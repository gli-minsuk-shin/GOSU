# Briefing Lab — 독립형 예약 연구 비서 개발 명세

상태: 최종 제품 설계 명세. 1차 독립형 fixture 프로토타입의 구현 범위는
[구현 현황](BRIEFING_LAB_IMPLEMENTATION.md)을 참고한다. 실메일/일정/위치 접근·LLM 연결·
백그라운드 예약 활성화는 아직 구현 완료를 의미하지 않는다.

## 1. 제품 구조와 확정된 선택

GOSU와 별도의 브라우저 UI + macOS 로컬 실행기로 개발하고, 이후 GOSU에 통합한다.
개발 UI 주소는 `127.0.0.1:4318`을 사용한다. 실제 예약은 브라우저 타이머에 의존하지 않는다.
기존 GOSU/Model Lab의 디자인, 모델 카탈로그, reasoning 선택, native provider와 공유 harness를
재사용한다. 범용 shell/cron 명령 실행기, 자동 메일 발송, 신청서 제출 기능은 이번 범위에서 제외한다.

사용자가 선택한 정책:

- Mac 로컬 실행. 잠자기·종료 중 놓친 예약은 복귀/로그인 후 최신 한 회차로 합쳐 보충한다.
- 결과는 전용 브리핑 화면 + 민감한 내용을 숨긴 Mac 알림으로 전달한다.
- 예약 시간은 수집 시작이 아니라 결과 공개 시각이다.
- 메일 본문은 계정·메일함·검색 조건과 선택한 LLM을 루틴별로 사전 허용한 범위에서만 전달한다.
- AI의 관심사 추론은 선택한 프로젝트·연구 주제와 확정된 사용자 피드백만 사용한다.
  메일 본문에서 관심사를 자동 학습하지 않는다.
- 선제 행사 알림은 예약 브리핑 안에 포함한다. 예약 외 긴급 알림은 제공하지 않는다.
- 설정 폼과 자연어 Copilot을 함께 제공하며, 대화로 만든 설정 변경안은 확인 후 적용한다.
- GOSU에는 선택한 프로젝트의 정보를 제공하는 최소 읽기 전용 연결부만 추가한다.

## 2. 독립된 두 브리핑

| 브리핑               | 포함 항목                                                                                    | 기본 일정 초안 |
| -------------------- | -------------------------------------------------------------------------------------------- | -------------- |
| 개인·연구 브리핑     | 이메일, 일정, 마감일 있는 to-do, 최신 논문; 선택적으로 날씨, AI 소식, 일반 뉴스, 학회 마감일 | 매일 오전 8시  |
| 연구과제 공고 브리핑 | 신규·변경·접수 임박 연구비/연구지원 공고, 관심 주제 관련성, 신청 조건, 중요 변경             | 매일 오전 9시  |

위 시간은 편집 가능한 초기값이며, 두 루틴 모두 사용자가 각각 저장·활성화하기 전에는 실행하지 않는다.
각각의 시간대·반복 주기·모델/reasoning·항목·검색 조건·실행 이력·알림·신규 항목 판정 상태를
독립 저장한다. 한 브리핑을 정지·삭제하거나 수집에 실패해도 다른 브리핑을 막지 않는다.
공개 소스의 수집 캐시는 공유할 수 있지만, 동일 항목을 어느 루틴에서 전달했는지는 별도 기록한다.
공유된 사용자 데이터 캐시는 동일한 접근 허용 범위 안에서만 재사용한다.

왼쪽에는 브리핑 종류별 루틴과 과거 회차를 계층형으로 표시한다. 중앙에는 핵심 요약 및 항목 카드,
오른쪽에는 최소화·폭 조절 가능한 Copilot을 둔다. 항목 선택·추가·삭제·일시정지·순서 변경을 지원한다.
결과 카드 숨기기와 향후 구독 항목 삭제를 구분하며 원본 메일·일정·GOSU task는 변경하지 않는다.

## 3. 연구 주제와 논문 우선순위

옵션에서 프로젝트별 연구 프로필을 만들고 브리핑에 연결한다. 필드는 주제 이름,
키워드/구문, 키워드별 중요도(1–5), 사용자가 승인한 동의어·국문/영문 대응어,
필수 조건 및 제외 키워드다. AI가 제안하는 관련 키워드는 승인 전 검색 범위에 추가하지 않는다.

- 키워드 입력·수정 직후 검색 조건과 순위 변화 예시를 보여준다.
- 제목·초록의 가중 키워드 관련성을 최우선으로 정렬하고, 최신성을 보조 기준으로 사용한다.
  인용 수나 대중적 인기를 앞세워 연구 주제에 덜 맞는 논문을 올리지 않는다.
- LLM은 실제 초록을 읽고 연구 주제와 연결되는 이유, 핵심 기여, 한계를 짧게 설명한다.
  관련성이 낮거나 근거가 부족한 항목을 높은 연구 품질로 포장하지 않는다.
- 카드에 순위, 매칭 키워드, 관련성 이유, 신규/수정 여부, 원문 링크, 초록/본문 중 읽은 범위를 표시한다.
- 고정된 정렬 정책 버전과 입력 해시를 기록한다. 모델·시행마다 순서가 무작위로 바뀌지 않도록
  기본 키워드 점수와 동점 정렬은 결정론적으로 계산하고, LLM 해석은 별도 보존한다.
- 프로필을 변경하면 기존 수집 자료를 재정렬할 수 있으며, 이미 전달한 브리핑을 조용히 덮어쓰지 않는다.
  공용 프로필 변경이 영향을 주는 루틴 목록을 적용 전에 보여준다.

신규 논문은 arXiv를 기본으로 기존 GOSU의 검색 공급자로 메타데이터를 보완한다.
DOI/arXiv ID·버전·발표/수정 시각·최초 발견 시각을 보존한다. `publishedYear`만으로 신규 여부를
판정하지 않는다. 과거 논문이 처음 발견된 경우와 실제 신규 발표를 구분한다.
기존 LiteratureService의 라이브러리/Obsidian 변경 경로 대신 읽기 전용 검색 공급자 계층을 재사용한다.

## 4. 연구과제 사이트 등록·국가별 발견

소스 관리 화면은 `URL 직접 추가`와 `사이트 찾기` 두 진입점을 제공한다.

### 국가 선택과 위치

- 국가는 직접 선택할 수 있고 여러 국가 및 국제/다국가 프로그램을 추가할 수 있다.
- `내 위치로 국가 추천`을 눌렀을 때만 macOS 위치 허용을 요청한다. 기존 언어·시간대를
  실제 위치로 간주하지 않으며 IP 기반 위치 추정을 몰래 수행하지 않는다.
- 위치를 국가로 변환하는 데 필요한 OS 서비스 사용을 고지한다. 사이트 검색에는 국가 코드만
  전달하고 정확한 좌표는 LLM·검색 공급자에 보내거나 지속 저장하지 않는다.
- 위치 허용 거부/실패 시 수동 국가 선택이 그대로 동작한다.
- 추정 국가는 사용자가 확인한 뒤 저장한다. 여행·출장으로 위치가 바뀌어도 구독 국가나 예약
  시간대가 자동 변경되지 않는다.
- 지원기관 국가, 신청 가능한 기관/연구자의 국가, 사용자의 현재 위치를 별도 개념으로 취급한다.
  현재 위치만으로 신청 가능하다고 판정하거나 해외 공고를 자동 제외하지 않는다.

### 사이트 후보와 구독

- 국가·연구 키워드로 공식 정부/연구지원기관/재단 소스를 검색한다. 초기 공식 디렉터리와
  실제 공개 웹 검색을 함께 사용하며 고정된 몇 개 사이트 목록으로만 제한하지 않는다.
- 후보마다 기관명, 국가/지원 범위, 공식 출처 검증 상태, 분야, 실제 공고 페이지 링크,
  수집 가능 방식, 로그인 필요 여부, 최근 확인 시각을 보여준다.
- 사용자가 선택한 후보만 구독한다. 추천됐다는 이유만으로 새 사이트를 계속 수집하지 않는다.
- 직접 추가한 URL은 접근·공고 추출 미리보기를 먼저 제공한다. 공식 여부가 확인되지 않으면
  사용자 등록 소스로 명시하며 공식 소스라고 표시하지 않는다.
- 공개 API/RSS, 공개 HTML, 명시적으로 허용한 브라우저 조회 순서로 지원한다.
  검색 스니펫만으로 공고 내용·마감·지원 자격을 확정하지 않는다.
- 로그인, CAPTCHA, 동적 페이지, 첨부 공고문 해석 실패는 소스별 `확인 필요/부분 수집`으로
  표시한다. 지원하지 않는 사이트도 저장할 수 있지만 자동 수집 가능 여부를 숨기지 않는다.
  임의 사이트가 모두 즉시 자동 수집된다고 보장하지 않는다.
- URL 검증은 리다이렉트와 DNS 결과까지 포함해 내부망/localhost 접근을 차단하고,
  조회 시간·응답 크기·첨부 형식을 제한한다. 실행 파일·매크로는 실행하지 않는다.

### 공고 결과

공고번호/세부 과제 ID, 기관, 국가/국제 범위, 원문, 발표·수정·최초 발견 시각,
접수 시작·마감·원래 시간대, 신청 조건, 연구 주제 관련성, 지원 규모/통화/기간(명시된 경우),
변경 사항을 보존한다. 목록 요약 마감보다 세부 공고문을 우선 확인한다.
통합 공고의 모든 세부 과제에 동일한 마감일을 덮어씌우지 않으며 날짜만 있을 때 시각을 발명하지 않는다.

소속기관 국가·기관 유형·경력 단계는 선택 입력이다. 원문 근거와 사용자 입력이 충분할 때만
`조건 부합 가능/조건 불일치`를 표시하고, 나머지는 `확인 필요`로 남긴다. 신청 가능 여부의 최종
확인은 공고문 및 담당기관에 달려 있음을 표시한다. 불확실한 자격 때문에 결과를 숨기지 않는다.

신규·수정·마감 연장·접수 종료를 구분하고 공고번호와 기관을 기준으로 교차 게시 중복을 묶는다.
본문 내용 해시로 실질적 변경을 추적한다. 관심 주제 관련성으로 정렬하며 마감 임박 항목은
별도 표시한다. 자료가 없으면 신청 요령이나 지원 금액을 LLM이 채우지 않는다.

초기 검증용 공식 사이트 예시(사용자 국가를 추정하는 기본값이 아님):

- 한국: [IRIS 사업공고](https://www.iris.go.kr/contents/retrieveBsnsAncmListView.do).
- 미국: [Grants.gov 검색](https://www.grants.gov/web/grants/search-grants.html).
- EU: [Funding & Tenders Portal](https://ec.europa.eu/info/funding-tenders/opportunities/portal/).

## 5. 나머지 소스와 데이터 경계

- 메일: 기존 Apple Mail 계정의 허용된 메일함과 검색 조건만 고정된 조회 전용 AppleScript로 읽는다.
  LLM 작성 스크립트, 보내기/삭제/이동/읽음 변경, 첨부 실행은 금지한다. 본문 전체는 실행 중에만
  처리하고 일반 로그에는 남기지 않는다. 조회 실패와 새 메일 없음을 구분한다.
- 일정: Apple Calendar의 사용자가 허용한 캘린더를 EventKit 어댑터로 조회한다.
  OS 허용과 별개로 앱 도구는 읽기 전용으로 제한한다. 반복 일정·종일 일정·원래 시간대를
  보존하고 취소된 일정은 제외한다. 참석자 목록 등 불필요한 개인정보는 LLM에 전달하지 않는다.
- To-do: 명시적인 마감일이 있는 미완료 task만 포함한다. 보관/삭제된 프로젝트와 task는 제외한다.
  GOSU DB를 직접 열지 않고 허용된 읽기 전용 스냅샷을 사용한다. GOSU 종료 시 마지막 스냅샷의
  시각·오래된 정보임을 표시하며 최신 상태라고 주장하지 않는다.
- 날씨: 사용자가 정한 도시의 Open-Meteo 예보를 결정론적으로 정리한다. 위치 사용은 필수가 아니다.
- AI 소식·일반 뉴스: 선택한 RSS/Atom·공식 발표 소스에서 동일 사건을 묶고 원문을 연결한다.
- 학회/행사: 선택한 연구 주제로 공식 학회·기관 소스를 찾아 연도, abstract/full-paper 마감,
  시간대를 확인한다. ML 관심사에는 ICLR·ICML·NeurIPS 같은 후보를 포함한다.
  확인되지 않은 날짜는 확정 마감일로 알리지 않는다.

## 6. 예약·전달·실행 엔진

각 루틴은 매일, 특정 요일, N일마다, N주마다, 매월 및 여러 시각을 지원한다.
`bi-daily/bi-weekly` 대신 `2일마다/하루 두 번/2주마다/주 두 번`으로 표시한다.
시작일과 IANA 시간대를 저장하고 다음 5회 전달 시각을 미리 보여준다.
초기 시간대는 Asia/Seoul이며 위치 추정과 독립적으로 수정한다.

전달 30분 전 준비하고 5분 전 최신 변경을 한 번 확인한다. 정각까지 검증된 부분은 공개하고
미완료·실패 소스를 표시한다. 보충 결과는 같은 회차의 수정 이력으로 저장하며 알림을 반복하지 않는다.
모든 소스가 실패했을 때 정상적인 빈 브리핑으로 표시하지 않는다. 각 항목의 실제 수집 기준 시각을 보존한다.

잠자기·종료 중 누락된 예약은 복귀/로그인 후 최신 한 회차로 합친다. 예정 및 실제 전달 시각을
구분한다. 장기간 꺼져 있던 동안의 모든 회차를 연속 LLM 호출하지 않는다.
루틴/예정 회차 고유키, 실행 lease, 체크포인트, 재시도 예산으로 중복 트리거와 재시작을 처리한다.
한 루틴의 전달 이력이 다른 루틴의 신규 결과를 소비하지 않게 한다.

DST 중복 시각에는 한 번 실행하며 없는 시각은 다음 유효 시각을 사용한다.
매월 존재하지 않는 날짜는 말일로 조정하고 미리보기에 표시한다.
일시정지/삭제는 해당 루틴의 진행 중 작업·후속 알림도 중단하며 과거 결과는 별도 보관한다.
알림 권한이 없어도 inbox 저장은 계속한다. 일반 알림에는 메일·일정·공고의 민감한 내용을 넣지 않는다.

## 7. 공유 harness·메모리·인터페이스

`apps/briefing-lab` UI/API, `packages/briefing-core`의 OS 독립 작업 엔진,
Swift macOS 호스트(AppleScript/EventKit/위치/Keychain/알림/사용자 LaunchAgent 등록)로 분리한다.
시스템 crontab과 루트 권한을 사용하지 않는다. 로컬 API는 loopback 전용, 인증 토큰,
Host/Origin 검증을 적용하며 데이터는 Keychain 기반 키로 암호화해 저장한다.

공유 계약은 BriefingRoutine(kind, schedule, profile, sources, invocation), BriefingRun,
SourceEvidence, InterestProfile을 중심으로 둔다. 확장 계약은 FundingSourceCandidate,
FundingOpportunity 및 읽기 전용 SourceDiscovery/Calendar/Location/GosuSnapshot 어댑터다.
기존 GOSU/Model Lab 타입에 연구과제 전용 상태를 밀어 넣지 않는다.

실행 흐름은 수집 → 변경/중복 판정 → 관련성 선별 → 요약/중요도 판단 → 출처/날짜 검증 → 전달이다.
native Codex·Claude 어댑터와 동적 모델/ reasoning 카탈로그, context budget, 공통 연구 정책을
재사용한다. LLM 동시 작업은 기본 2개이며 두 루틴이 공정하게 실행 기회를 얻도록 한다.
각 작업에는 해당 루틴의 허용된 자료만 주고 필요한 내용을 읽기 도구로 추가 조회한다.

변경 없는 자료는 원문 해시·프롬프트 버전·모델 설정 기반 캐시로 재사용한다.
날씨와 날짜 계산에는 불필요한 LLM 호출을 하지 않는다. 새 소스의 내용, 메일, 웹 페이지,
과거 요약은 권한이나 지시를 바꿀 수 없는 불신 자료로 취급한다.
메일·일정 본문을 공개 웹 검색어에 끼워 넣지 않는다.

카드마다 원문·수집 시각·관련성 이유와 읽은 범위를 표시한다. 진행 상태는 실제 수집 건수,
제거된 중복, 요약/검증 단계, 오류, 모델 사용량만 보여주고 내부 reasoning은 노출하지 않는다.
사용자가 확정한 관심사와 중요/관심 없음 피드백만 영구 메모리에 저장한다.
메모리는 편집/삭제 가능하며 현재 날짜·마감일의 새 근거 대신 사용하지 않는다.

기존 구독 계정 provider를 사용하고 API-key 유료 fallback은 추가하지 않는다.
인증 만료나 quota 제한은 해당 LLM 작업을 중단하고 표시한다. 다른 provider로의 개인정보 전달은
사전에 허용되지 않았다면 자동 전환하지 않는다. 요약 보관 초기값은 90일이다.

## 8. 개발 순서와 필수 검증

1. 두 루틴의 설정·예약·프로필·실행 이력과 fixture 브리핑 화면을 구현한다.
2. 키워드 논문 정렬, 국가별 소스 발견/직접 등록, 공개 과제 공고 수집을 구현한다.
3. 읽기 전용 GOSU 연결과 macOS 메일·일정·위치·알림 권한 흐름을 붙인다.
4. 설치본으로 백그라운드 예약·재시작 복구와 두 브리핑의 독립 전달을 확인한다.
   GOSU 내부 화면 통합은 이후 별도 작업이다.

회귀 테스트 요구사항:

- 개인·연구 브리핑과 연구과제 브리핑의 서로 다른 시각/주기/알림/중지/실패 격리.
- 공유 수집 캐시를 사용해도 전달 이력, 민감한 자료 권한, 프로필 변경 적용 범위가 섞이지 않음.
- 키워드 가중치·동의어·제외 조건·제목/초록 매칭·재정렬·동점 순위·관련성 이유의 일치.
- 수동 국가와 위치 추천, 위치 거부, 여행 중 국가 불변, 다국가/국제 프로그램, 현재 위치와 자격 분리.
- 사이트 후보 다중 선택·직접 URL·중복 소스·공식 여부 미확인·미지원 페이지·로그인/CAPTCHA·SSRF.
- 공고 신규/수정/마감 연장/종료, 교차 게시 중복, 세부 RFP별 다른 마감, 금액·자격 누락/충돌.
- 모든 반복 주기, DST/말일, 사전 준비/정시 공개/부분 결과, 잠자기/로그인 보충, 중복 실행 방지.
- 메일 권한 범위, 쓰기 명령 차단, 읽음 상태 유지, 본문 미다운로드, 악성 원문 지시 차단.
- 반복/종일/취소 일정, 마감일 없는 task 제외, 오래된 GOSU 스냅샷 및 연결 해제.
- LLM 인증/quota/취소/재시도/출처 없는 주장/메모리 삭제.
- 실제 스크린샷으로 사이드바, 긴 카드, 독립 스크롤, 폭 조절, 두 시간표와 필터를 확인.

실메일·일정·위치는 사용자 지정 시험 범위의 opt-in packaged smoke로만 확인한다.
앱 행동 변경마다 실패를 재현하는 집중 테스트를 추가하며 affected package 전체 테스트,
typecheck, lint, format, production build를 통과시킨다. 공유 harness 변경에는
`pnpm test:agent-runtime`도 필수다. 개발 문서는 Obsidian repository-docs 미러에 동일하게 저장한다.

## 근거와 구현 시 확인할 제약

- [Apple 자동화 권한](https://support.apple.com/guide/mac-help/allow-apps-to-automate-and-control-other-apps-mchl108e1718/mac): OS 허용 자체가 조회 전용 도구 계약을 대신하지 않는다.
- [Apple 예약 실행](https://developer.apple.com/library/archive/documentation/MacOSX/Conceptual/BPSystemStartup/Chapters/ScheduledJobs.html): launchd 권장 및 잠자기/종료 제약.
- [Apple EventKit](https://developer.apple.com/documentation/eventkit/accessing-the-event-store): 일정 접근은 별도 권한 경계다.
- [arXiv API](https://info.arxiv.org/help/api/user-manual.html): 발표·수정·버전과 초록을 구분한다.
- [Open-Meteo](https://open-meteo.com/en/docs): 배포 전 용도별 이용조건·표시 의무를 확인한다.
- [IRIS](https://www.iris.go.kr/main.do): 목록의 접수 기간이 기관 승인/통합 공고 때문에 세부 접수 기간과 다를 수 있다.
- [Grants.gov 신청 자격](https://grants.gov/learn-grants/grant-eligibility): 외국 신청자 자격도 개별 공고 조건에 따라 확인한다.
