## Apple Mail buttons were disabled because links were read last

User report: the "open in Apple Mail" icon on Briefing emails was disabled. The button requires a
canonical `message://` link built from the message's Message-ID. The reader fetched every body
first and only then the Message-IDs, inside a 60s read limit that returns partial results.

With the user's permission, a read-only Mail diagnostic (timings, lengths and link validity only;
no subjects, bodies or IDs recorded) timed the newest eight messages of each All Mail: every
Message-ID was a valid link and took 20-840ms, while `content()` stalled for about 61s on two of eight
messages of one account. One stalled body used up the read limit before the link pass began, so no
message received a link.

Change: the reader fetches Message-IDs in their own pass before bodies; bodies still come before
the optional source proofs, which reuse the fetched ID. The ordering test now asserts link, body,
proof.

## Found papers were not summarized, and the failure was not shown

User report: "새 논문 10개를 찾았습니다" with 0 summaries. The usage ledger after installing 0.58.95
showed Claude working again, but the last summary call of each run failing: Sonnet 5 after 24s and
Haiku at 179.7s, just under the 180s routine deadline that every Briefing analysis used. Paper
batches hold six papers with five long template fields each, and a validation retry sends the
rejected draft back, so a Claude batch can take several minutes.

Three changes:

- Deadlines: email analysis gets 5 minutes and paper analysis 8 minutes, and the routine passes its
  deadline to the provider as the turn limit so Claude's own 5-minute default does not undercut it.
  The overall 20-minute generation limit is unchanged.
- Batches: an AI summary batch that fails no longer aborts the whole run. Its reason is recorded
  as a warning and later batches continue. Cancellation, changed settings or ownership, consent,
  permissions, a lost login and an unavailable model or reasoning still stop the run, and a run in
  which no batch succeeded still fails with the first batch's reason.
- Visibility: the generation header now shows a failed run's reason after its progress view closes,
  and a completed run with failed summary batches (`summaryFailures`) shows how many failed and
  why. Completed runs without summary failures keep the compact header.

The 24s Sonnet 5 failure was not captured: a failure-only CLI logger was armed but no run happened
before it was removed. The new header shows that reason on the next occurrence.
