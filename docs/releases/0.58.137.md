## An email whose summary failed still shows that it arrived

User request: "이메일 요약이 실패해도 제목, 보낸이, 보낸 시간은 뜨게 해줘. 요약만 빠지게. 그래야 사용자가
적어도 이메일이 온건 알 수 있잖아." Until now only verified summaries were written to the briefing, so
the mail of a failed batch, a rejected summary, or a run that stopped on a lost login or an unavailable
model was invisible until a later briefing succeeded.

- After the summary batches (`keepUnsummarizedMail`, in the `finally` of the batch loop, so it also
  runs when the run is about to fail) every selected email that was not saved is written to the day's
  briefing with its subject, sender, received time, account and link to the original, an empty summary
  and importance `uncertain`. The run's warnings say how many were kept this way.
- The store already reads an empty email summary as "not summarized yet" everywhere: the mail read
  plan does not exclude it, today's known items leave it out, the completion notification does not
  count it, and the assistant's memory skips it. So the next briefing reads and summarizes the mail
  again; on the same day that summary replaces the empty entry in the feed (same item id), and the
  per-item "다시 요약" works on it.
- Never kept: a sign-in code or password-reset mail (it is not selected for AI at all, and its subject
  can hold the secret), a batch withheld for secrets (marked handled before), and anything of a run
  the user cancelled. Keeping the entries never hides the error that ended the run.
- Shown as: the title with a badge "요약 실패 · 원본 확인", sender and time as for any mail, the line
  "AI 요약 실패 · 메일이 온 것만 표시합니다 · 다음 브리핑에서 다시 요약", and an explanation in the opened
  card instead of "이전에 저장한 AI 요약". The "first to check" list says "AI 요약 실패 · 원본 메일을
  확인하세요" for such a mail.

## The "new briefing" shortcut is a setting

User request: ⇧⌘Enter should be changeable in the shortcut settings. It is now the fourth entry of the
app shortcuts (`briefingRun`, default `CommandOrControl+Shift+Enter`) beside Calendar, To-do and
Briefing Lab: Settings → Shortcuts changes it, turns it off, and refuses a chord another shortcut or the
assistant uses; the View menu lists "새 브리핑 실행" with the chord. Chords may now use Enter (main or
numeric keypad). A settings file saved before this release has no such key and loads with the default;
the file is only rewritten when the user saves the shortcuts.

- The main process catches the chord before any page or frame (the same hook as the other shortcuts),
  so it works wherever the focus is. The app shell starts a briefing only while the Briefing Lab feed is
  showing; from another screen the chord opens Briefing Lab, so a stray press never spends a run.
- The hardcoded ⇧⌘Enter listeners of 0.58.136 (in the Briefing frame and in the shell) are gone inside
  GOSU, or the old chord would keep working after a change. On its own (outside GOSU) Briefing Lab keeps
  the default chord. The button's tooltip shows the chord the shell reports, or none when it is off.

## Full Disk Access: kept across updates, and a first-run permissions helper

User request: grant Full Disk Access once and keep it, or else open the right settings screen; and a
helper at the first start that makes the needed permissions easy to set.

- **It already persists.** macOS ties the grant to the app's code signing requirement, and every build
  has the same one: `identifier "science.gosu.desktop" and certificate leaf = H"093f0751…4264"`
  (checked on the installed 0.58.136 and the two previous apps; `verify-update-continuity.mjs` gates
  every install on it). Nothing had to change for that. GOSU cannot grant it itself.
- **Check** (`fullDiskAccessState`): lists `~/Library/Mail`, the folder the fast mail read needs;
  macOS refuses silently without the permission and nothing in the folder is opened. `granted`,
  `missing`, `not-needed` (no such folder: Mail was never used) or `unknown`.
- **Notice** at start while it is missing: what it is for, that one approval survives updates, that
  GOSU must be restarted after switching it on, with "시스템 설정 열기" (the Full Disk Access pane),
  "다시 확인" and "닫기" (remembered on this Mac).
- **Permissions helper** (`PermissionsHelper`): opens once at the first start on a Mac and from
  Settings → Briefing Lab ("권한 도우미"). Three rows: Full Disk Access with its state, Automation (Mail)
  and Calendar with when macOS asks for them; each has a button to its System Settings pane. Only fixed
  pane URLs are opened; no setting is changed by GOSU. The Settings → Briefing Lab permission row also
  has "전체 디스크 접근 권한" with its state.

## "추가" and "나중에" for the library question

User request with a screenshot: the assistant ended an answer with "이 설명도 Briefing Lab 논문 요약
라이브러리에 추가할까요?" and there was nothing to press. The offer card with its buttons exists, but
since 0.58.133 it is hidden when the answer only read papers that are already in the library, which
was the case here; the question the model wrote itself stayed.

- An answer that asks the library question in its own words (`asksPaperLibraryQuestion`, the same
  wording the server accepts a typed "응" for; quoted text and code do not count) now gets two buttons
  right under it, "추가" and "나중에", without a card that repeats the question. "추가" saves the
  explanation through the existing, verified save path; the question sentence is not part of what is
  saved; a paper already in the library is reused.
- Such an answer refers to the papers it read even when it names them by a short form, so the save
  finds its source. Without a question of its own, an answer about saved papers still shows no offer.
- The card's primary button reads "추가" everywhere (it was "보관함에 추가").

Regression tests: `briefing-generation.test.ts` (kept mail on an unavailable model, on a timed-out
batch with same-day replacement, on a rejected item; +1: never a sign-in code mail, nothing for a
cancelled run), `src/briefing-insight-card.test.tsx` (+1 rendering), `app-shortcuts.test.ts` (default,
old settings file, Enter chords, changed chord frees the old one, menu, shell wiring),
`shortcut-settings.test.tsx` (the new row), `global-briefing-view.test.tsx` (run request relayed, chord
reported, no page listener), `src/briefing-run-shortcut.test.tsx` (standalone default, embedded
