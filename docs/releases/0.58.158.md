## A paper the 논문 요약 AI was asked about is visible while scanning

"논문요약에서 AI 질의응답한 논문은 AI 마크가 눈에 띄게 박히고 테두리 박스 색깔도 바꿔줘. 그래서, 좀더
쉽게 구분할 수 있게."

The only mark was a small counter in the row's tool strip, which is invisible while scrolling a
library of a hundred cards. The card now carries an `AI` badge beside its title, where the eye
already goes for the title and the New badge, and the card itself takes a tinted ground with a solid
green bar down its left edge.

The first attempt set `border-color` on `.briefing-card.briefing-insight-card.is-asked-ai` and
changed **nothing on screen**. Inside `.briefing-reading-list` every card gives up its border, radius
and shadow so the list can draw a single box, and that rule carries the same specificity while
loading later. The tests passed throughout, because they asserted the class was on the element —
which it was. Only rendering the real stylesheet showed the screen was identical. The mark is now an
inset bar, the reading-list selector is spelled out, and a regex test pins it so the next change
cannot quietly return to a no-op.

## Model Lab: the assistant can use the window, and the resize bar can move

This section is another session's work, recorded here because it shipped in this package; the
numbers below are its measurements, taken in a real browser against the running dev server.

`.model-chat--sidebar` carried `max-height: 900px`. In a 1,400px window the panel stopped at 900 and
left 429 empty pixels under it while the conversation had 641; with the cap gone the conversation
measured 1,127. Composer and header padding came down, 174→162 and 84→78. A regex test pins the rule
so the cap cannot come back.

The graph's floor was a flat 520px which, with the 252px model list, spent the entire budget: a
workspace of 1,040px or less gave the resize bar **zero** travel, and 1,100px gave it fourteen. The
floor is now `min(520, 38% of the workspace)`, and travel measures 29/79/116/178px at
960/1,040/1,100/1,200. One existing expectation moved with it —
`availablePanelMaximum(1280, 390, 190, 420)` from 356 to 390 — and was updated rather than worked
around.

Known and not fixed here: at scroll 0 the Model Lab chat panel overflows the viewport by 39px, so
the input row sits just below the fold until the page is scrolled slightly. It predates both
changes — the panel is sticky at full viewport height while starting 71px down the page — and
fixing it means changing how that page scrolls.
