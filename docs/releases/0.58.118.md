## Rating an unread email marks it read in Apple Mail

User request: when 관심 있음 or 관심 없음 is pressed on an email in Briefing, change an unread email to
read automatically, and keep Apple Mail in sync. The user approved the proposed design.

- Pressing either rating on an email that is still unread (not already read at briefing time and not
  already marked by GOSU) also runs the existing single-message "읽음으로 변환" path
  (`/mail/mark-read`): the server checks it is the same message and Apple Mail link, follows the
  request confirmation policy (a per-request consent dialog when set to ask), marks only that message
  read, records `mailMarkedReadAt` in the briefing record and never opens, sends or deletes mail.
- `markMailReadFor` in `mail-read-status.tsx` is shared with the manual button: the read status next
  to the title shows progress, turns to read on success, shows the reason on failure and "확인 필요"
  when the write could not be confirmed, exactly like the manual button. A message marked in this
  session is not written again, so changing the rating does not touch Apple Mail twice; clearing a
  rating does nothing.
- The rating is saved independently; a mark-read failure does not undo it.
- Saved briefings and the live briefing view use the same email disclosure, so both behave this way.
