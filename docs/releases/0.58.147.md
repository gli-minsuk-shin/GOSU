## The Research Notes grant survives an app update

User report: "이거 연구노트 접근 허용하면, 앱을 update 해도 계속 허용이 되어야지. update 할 때 마다
설정에서 허용눌러야하면, 너무 번거롭잖아."

- Traced to the identity, not to the update. `VaultAccess.open()` named a vault by hashing the
  canonical path **together with the folder's device and inode**, and the saved grant was compared
  by that name. macOS changes a folder's inode on its own: iCloud Drive evicts and re-materializes a
  folder, a volume is remounted, a backup is restored. When it changed, the saved grant no longer
  matched the folder in front of the user and Settings → Agent showed "이전에 허용한 폴더" with the
  Allow button again, right after an update because that is when the app is next opened.
- A vault is now named by its canonical path alone. `dev:ino` is still captured and still checked
  during a walk (`assertRootIdentity`), which is what it is good for: noticing that the folder was
  swapped underneath a read in progress. It is no longer part of the vault's name.
- Grants written by earlier versions are still recognized: `open()` also returns the old formula's
  id as `legacyId`, and `matchesGrant` accepts either. Nobody has to re-authorize a second time.
- This release is the one that changes the id, so the grant has to be given once more after
  installing it. From here on it survives.

## A quote reads the history and picks a subject it has not used

User report: "여기 격언 list 를 보면 뒤로 가면 갈수록 비슷한 격언을 내뱉는데, 왜 그런거지? 너무
성능이 안좋은 LLM 을 써서 context size 가 커져서 망가지는건가?" — then: "History 를 읽어서 말하지
않은 앞에 안나온 다른 주제로 격언을 내보내게 하자."

- Not the model and not the context. The quote job carries no tools, no thinking and a prompt of a
  few lines plus the last ten quotes. The cause was GOSU's own: `dailyQuoteSubject` picked the
  subject from the **date alone**, so every refresh on one day asked for the same subject. On
  2026-09-22 that subject was "plain human folly", which is why the list filled with variations of
  one joke.
- The subject now moves with the day's written count and, more to the point, skips every subject the
  kept history already used: `dailyQuoteSubject(date, written, used)` walks the fourteen subjects
  from the day's offset and returns the first one that is free.
- The model is told which subjects to avoid (`avoidSubjects`) and returns the subject it actually
  wrote (`subject`), which is stored with the line. So the next request avoids what was really
  written, not what was merely suggested. Two sentences were added to the instructions: do not reuse
  the shape, opening or joke of a recent line.
- A line written by an older version carries no subject; it is simply not counted as used.

## "AI 지침" on a server is always open

User report: "연결 session 에서 AI 지침이 최소화되어 있어서 잘안보임. 이거 항상 expand 된게 바꾸자."
The per-server instructions were a closed `<details>`, which hid the field so well that a server

label above the field.

## One row per Codex account in 사용량

User report: "사용량에서 codex · GOSU 랑 ChatGPT 모델을 구분할 이유가 있나? 합치면 안됨? 헷갈리잖아."

- Both rows were one account. GOSU stores the connection label with each recorded turn, and turns
  recorded before it had read the Codex login carry the unlabeled key `codex:unknown` ("Codex").
  The rows were written with `on conflict do nothing`, so the older rows keep the older label
  forever and the same account appears twice, once as "codex" and once as "ChatGPT".
- `foldUnlabeledCodexUsage` folds the unlabeled turns into the labeled Codex connection when the
  range holds exactly **one** labeled Codex connection, which is the case that produced the
  complaint. With none, or with several (a ChatGPT login and an OpenAI API key in the same range),
  the owner is genuinely unknown and the rows stay apart rather than being guessed into one.
- It runs once, on the rows the report is built from, so every part of the screen agrees: the
  connection rows, the model and project breakdowns, the per-day series, the Lecture rows, and the
  drill-down that filters by the merged connection.
- Stored rows are not rewritten. This is a reading of the data, so a future release can change it
  without having lost anything.

## 논문 요약 AI has its own model role

User request: "논문 요약에서 AI 질문 하는걸 논문 요약 AI 를 따로 만들어서 질의응답하게 하자. Agent
AI 설정에서도 논문 요약 AI 에 할당하는 모델도 정할 수 있게 하고."

- Settings → Agent has a new row, "논문 요약 AI · 논문 분석과 논문별 질의응답", with the same three
  choices as the other Briefing roles plus "기존 설정". Until it is set it follows the Briefing role,
  so nothing changes for anyone who does not touch it.
- `usageChoice(policy, usage)` is now the single place that answers which role a usage runs on, and
  `routedModel` is written in terms of it. The paper-summary ingestion asks for `'paperSummary'`
  instead of `'briefing'`.
- The Briefing row's label narrowed to "Briefing · 이메일 요약", because paper summaries are no
  longer part of it.
- The per-paper question-and-answer chat this role is for is not in this release; the role and its
  routing are.
