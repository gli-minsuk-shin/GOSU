## `/new` and `/compact` in every AI chat

User request: "AI project chat과 AI 비서 chat에서, Model copilot 모든 AI chat에서 /new 와 /compact 기능을
넣어서 context length가 너무 길어지는 걸 관리할 수 있게 하자".

- One parser for the three chats, `@gosu/ui/chat-slash-commands`. A message is a command only when
  it is nothing but the command (NFKC, case-insensitive, surrounding space ignored), so "/compact
  the related work section" stays an ordinary question. A command is handled by GOSU: it is never
  sent to a model, never queued and never stored as a message. While the draft is one word starting
  with "/", a small menu lists the matching commands with one line each; Enter on a half-typed
  command completes it instead of sending it.
- `/compact` is the existing compaction, asked for instead of waited for.
  `compactConversationNow` is `prepareConversationContext` without the "only under pressure" exit:
  everything but the latest four messages becomes part of the summary, an existing valid checkpoint
  is extended (nothing is summarized twice), and when the checkpoint already covers everything no
  model is called. The summarizer, its model (Settings → Agent), the usage kind
  `context_compaction`, the checkpoint store and its stale guard are the ones a turn uses, so the
  next turn simply finds the checkpoint. Records are never deleted. The command reports how many
  messages it folded in this time, and the context meter shows the new plan.
- `/new` starts an empty context.
  - AI 비서 and Model Assistant keep one conversation per routine or model revision, so `/new` marks
    where the context starts (`contextStartsAt`): later turns are given the records after it, the
    checkpoint of the ended context is dropped, and a quiet line in the transcript says "여기부터 새
    대화 · 위 메시지는 AI에 전달되지 않습니다". Earlier messages stay on screen and on disk. The
    model cannot reach them either: `search_conversation` reads the current context only, like a
    new Project Chat session cannot read another session. The line survives a reload (server state
    for the assistant, the stored chat session for Model Lab), and after a reload the meter shows
    the latest report of the current context, never one from before the line.
  - Project Chat already has sessions, so `/new` is the existing "＋ 새 채팅" with the same rules
    (review mode, the 100-session limit). Staged attachments are released as on any session change.
- Both commands are refused while an answer is running, with a sentence that names the command; they
  are not queued. AI 비서 also refuses them while questions are waiting in its queue, because those
  were written for the current context. A question typed while a Project Chat compaction runs is
  held (Send is disabled) instead of failing with "busy", and Stop cancels the compaction through
  the same control that cancels a turn's own context preparation.
- Project Chat's `/compact` is a new IPC command, `compactSession` (strict input: project, session
  and the model a turn would use). Expected failures are outcomes with a bounded reason, not thrown
  provider text: no summarizer wired, context size unknown (a guessed window is not trusted),
  provider without GOSU-side context (Hermes), settings changed while it ran, empty or oversized
  summary, summary that still does not fit, model call failed, cancelled. Each has its own sentence
  in both languages. The fixed part of the prompt is sized from the saved agent profile; the next
  turn plans again with its own question, tools and memory. `send` and `compactSession` share
  `resolveProjectContextWindow`, which was moved out of `send` unchanged.
- The context meter's details, the one place that shows how long the context is, now also say how to
  shorten it (`/compact`, `/new`). The meter is shared by the three chats.
- Known: the report of a `/compact` is kept in memory for the session view. The stored context
  report belongs to an attempt, and a command has none, so after restarting GOSU the meter of a
  Project Chat session or of the assistant shows the last turn's report until the next turn runs.
- Known and unchanged: Claude Code and Codex keep their own native transcript for a running thread.
  GOSU's summary shortens what GOSU sends at the start of the next turn; a provider's own count of a
  live thread is reported by the provider.
