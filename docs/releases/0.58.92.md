## Diagnosis

- Mail: read-only timing (counts, dates and elapsed time only; the user allowed the macOS automation
  prompt). The large Gmail All Mail (117,067 messages) lists newest first, but each Mail Apple Event
  took 3–4s and later 17s; a 3,171-message All Mail took 0.12–0.66s. A date-bounded `whose` over All
  Mail hit the 2-minute Apple Event timeout. System load averages were 170–205 on 10 cores while
  seven `mqar.py` experiment processes (started from another Claude Code session) and two backup
  scripts ran; no process from this release work remained. The reader's 15-second metadata budget
  ended before one candidate, throwing `mail_timeout_metadata`.
- Papers: `export.arxiv.org` returned HTTP 429 "Rate exceeded." to every request from this network,
  including manual requests while GOSU was not running. Crossref and OpenReview returned 60 results
  each with GOSU's User-Agent, and a read-only discovery run with those two indexes found nothing
  within the recent window and keywords, so discovery threw the generic
  `papers_discovery_incomplete`.

## Change

- Mail reader: the metadata scan budget is 50 seconds (`APPLE_MAIL_METADATA_BUDGET_MS`) inside the
  unchanged 60-second process deadline, whose checkpoint still returns earlier candidates. Once at
  least two received dates confirm newest-first order, the first message older than the window ends
  the scan; any out-of-order date keeps the previous bounded scan. Targeted search is unchanged.
- Paper discovery keeps which index failed and why (`PapersDiscoveryIncompleteError`), including for
  a reused candidate pool. When only arXiv was rate limited, the notice says arXiv limited requests
  and Crossref·OpenReview had no new papers in the window; otherwise it names the indexes that did
  not respond. A plain error keeps the previous notice.

Not changed: the arXiv rate limit itself and experiment load are outside GOSU. A slower "read the
whole window for minutes" mode was considered and not implemented after the load cause was found.
