## Paper links from Google Scholar alerts

User question: why some paper summaries open their external link and others do not. The link icon is
active only for a saved `https://` source URL; GOSU never guesses one. arXiv search results and
DOI/OpenReview lookups always have one. Google Scholar alert papers had one only when the alert text
itself contained a paper URL. GOSU reads a message body through Mail's plain-text `content()`, which
keeps the visible titles of an HTML alert but drops their hrefs, so most alert papers were built from
title/author lines alone ("원문 링크와 전체 내용을 확인하지 못했으며") and had no link. The preview is also cut
at 4,000 characters, so later papers of an alert were not found at all.

User choice: read the links from the alert's raw HTML source.

Evidence on the user's Mac (read-only, counts only, no titles or text printed): the five most recent
Scholar alerts in Gmail were found through Mail's index and read from their `.emlx` files (47–50KB,
no Mail request). Each had an HTML part with 13–14 links. Rebuilding candidates from a
`content()`-like plain text cut at 4,000 characters gave 5–8 candidates and 0 links per alert; adding
the HTML title links gave 11–12 candidates (the 12 cap) with 10 links each (arXiv, publishers and
repositories reached through Scholar's redirect).

Change:

- `htmlFromMailSource` finds the first `text/html` part of a raw message (nested multipart, folded
  headers, quoted-printable or base64, charset via `TextDecoder`; at most 262KB and depth 5), and
  `linksFromHtml` returns each web link's visible text and target (entities decoded, script/style
  ignored, deduplicated, at most 100). Nothing is fetched.
- The supervised body reader asks Mail for `source()` only for messages flagged `html`, only after a
  body was read and only up to 262KB (the existing source-proof bound), and streams it as
  `mail-source`; the host turns it into `links`. The connection flags messages whose sender or title is
  a Scholar alert (`isScholarAlertMessage`) and puts the links on the mail item as `mailLinks`, which are
  not saved with summaries.
- `scholarCandidates` uses an anchor only when its text is an article title and its target passes the
  existing `paperLink` rules (Scholar redirect unwrapped, tracking parameters removed, `https` only for
  non-DOI links, known publishers for direct links); `[PDF]`/`[HTML]` and domain-only anchors are never
  titles. A citation-only paper whose title equals an anchor gets that link with its bibliography and
  excerpt; linked titles the plain text did not reach are added with the link. The commercial filter
  still applies.
