## The suggested questions can be turned off

User request: "AI 켤때마다 자동 추천되는거 설정에서 끄고 켤 수 있게 해줘. Agent AI 설정에 넣어주면
되겠다."

- Settings → Agent has a new card, "AI 대화 추천 질문", with one switch: whether opening an AI chat
  also opens its suggested questions. On by default, so nothing changes for anyone who leaves it
  alone.
- It governs only what happens by itself. The suggestions button next to the composer still opens
  them, and turning the setting back on opens them again the next time a chat is shown.
- The switch calls no model. The suggested questions are sentences written in the page, so the
  setting has nothing to do with AI usage; the card says so.
- It is a user preference, kept where the other app-wide AI settings are kept
  (`gosu:user-preferences:v1`), and a stored file without the field means "on", which is what every
  version before this one did.
- Briefing Lab runs in a frame with its own storage, so the value travels on the navigation message
  the shell already sends: on load and again whenever the setting changes, without reloading the
  frame or losing a conversation. A message without the field leaves the frame's current value
  alone, so an older shell and Briefing Lab on its own both keep showing them.

## A question about one paper runs on the 논문 요약 AI model

0.58.147 added the role to Settings → Agent. This release makes the chat use it.

- `briefingChatUsage(policy, aboutPaper)` is the whole rule: a turn that carries a paper reference
  runs on `paperSummary`, and everything else on `briefingAssistant`.
- The role has to have a model first. While 논문 요약 AI is unset the paper turn keeps running on the
  assistant's model, exactly as it did before the role existed. Falling through to the role's own
  default would send it to the Briefing model, which the user may well have set to the fastest model
  for bulk email, and a conversation is not a bulk summary.
- A turn with no paper attached is never affected, whatever the role is set to.

## Still open from the same request

The 논문 요약 AI work the user asked for on 2026-09-22 is not finished. What remains, and why it is
not here: each piece writes to the sealed paper library or to another view, so it needs its own
tests rather than riding on this release.

- The conversation saved onto the paper, with an AI 대화 icon on papers that have one, and an
  "AI 질의응답" switch at the top of 논문 요약 that combines with the search, category, tag and date
  filters. A chat opened from a saved paper already carries that paper's library id
  (`paperReference.historyId === ''`, `paperId` the record's 64-hex id), so the record has a place
  to live; `PaperSummaryRecordSchema` is `.strict()` and the library seals each record once, so this
  needs a read-modify-rewrite method on `SharedPaperSummaryLibrary`.
- Reaching a paper's chat from Project Chat.
- 추가/나중에 buttons in the state where an answer holds no link the library can verify. The card
  there is a notice with no buttons today; making it actionable needs a way to send a prompt from the
  card, which the offer component does not have yet.
