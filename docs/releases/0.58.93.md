## Claude model list

User request on installed 0.58.92: the Claude model list lacked Fable 5.1 and Haiku.

Probe (one short "OK" request each through the local Claude Code subscription, explicit arguments):
Opus 4.8 control, Haiku 4.5 (with and without `--effort`) and Sonnet 5 answered on CLI 2.1.169.
Fable 5.1 returned HTTP 400 "Claude Code 2.1.169 does not support this model; version 2.1.251 or
newer". With the user's approval the CLI was updated through `claude update` to 2.1.272; the
claude.ai `max` login was preserved, and Fable 5.1 then answered at effort low and max.

Change: the Desktop Claude Code adapter publishes Haiku 4.5 (200K context), Sonnet 4.6, Sonnet 5,
Opus 4.8, Opus 5 and Fable 5.1 from one model table. Fable 5.1 is published only when the local CLI
version is 2.1.251 or newer. A requested model must be in the connected catalog, so an unsupported
model is rejected before a CLI call. The provider router recognizes Claude Code models from the
adapter's table, and Model Lab's standalone catalog lists the same models with the same gate.

## Briefing summaries use the assigned fast role

User report: email and paper summaries did not use the fast model configured in Settings. The saved
routing assigned Briefing to the fast role (Claude Code Sonnet 4.6, medium), but
`routedBriefingPreferences` skipped routing for every usage except lightweight drafts whenever the
Briefing chat had an explicitly selected model (the GOSU AI header showed Claude Code · Opus 5 ·
xhigh), so summaries ran on the pinned chat model.

Change: a model picked in the Briefing chat now applies to that chat (`briefingAssistant`) only.
Email/paper summaries (`briefing`) and lightweight drafts follow the role assigned in Settings. The
provider-permission check is unchanged: a role on a different provider still stops with
`model_routing_provider_permission_required`. The Settings note describes the new rule.

## Sidebar AI activity star

User request: show the star next to the row name rather than on the icon, make a finished task glow
yellow, and clear it on click.

Change: labelled rows (Briefing Lab, Paper summaries, Projects group, project folders, project
sections and Workspace destinations) render the star inside a `sidebar-row-label` span right after
the name, so existing grid columns (counts, menus) keep their positions and long names still
ellipsize. The icon-only AI assistant button keeps the star on its icon. A completed, unread result
is a filled star glowing yellow (`#f2b705` with a drop shadow) that gently twinkles; running work
keeps the drawn green outline. The star ignores pointer events, so clicking it clicks its row, which
acknowledges that scope as before. Reduced-motion users get static stars.
