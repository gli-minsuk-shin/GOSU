## Phase 2 of "every chat can reach everything": the AI assistant's research workspace

User choice after phase 1: the AI assistant writes real to-dos, research notes, the project
Literature library, and experiments (the user added experiment writes); manuscripts stay read only.
A requested write runs at once, as chosen for phase 1.

- Reads, offered whenever the project bridge is available and gated like the other project tools
  (Briefing "project read" plus private-AI approval, rechecked on each call):
  `read_research_notes` (the project's connected Obsidian notes: list, read with offsets),
  `read_literature` (records with authors, year, venue, DOI, review status, saved summaries),
  `read_manuscripts` (manuscript list, files and text of the last captured checkpoint, never live
  Overleaf) and `read_experiments` (ideas, metric points, recent runs).
- Writes, offered only when the user's own message names the target and an add/save/record verb
  (`explicitAssistantWrites`; denials and how-to questions grant nothing):
  - `create_todo` creates a GOSU to-do through the same task path as the reviewed UI button
    (`DesktopBriefingTaskActions.create`: replay-safe request id, active project check), mirrored to
    Apple Reminders only when the saved to-do setting enables a writable list
    (`assistantTodoCreator`). The chat instruction now creates requested to-dos instead of only
    proposing them.
  - `save_research_note` creates one new Markdown note in the project's Research Notes folder
    (`saveMarkdownForAgent`, create-only, idempotent per turn), labelled as the GOSU AI assistant.
  - `add_to_literature` adds papers returned by this turn's `search_papers` to the project Literature
    library. The records carry the observed public metadata (title, authors, year, venue, abstract,
    HTTPS link), never model-written text; `LiteratureService.addFromAssistant` upserts them as
    imported records (matched by DOI, arXiv id or fingerprint) within the 500-record limit.
  - `add_experiment_idea` and `record_experiment_metric` (the locked primary metric; fails without a
    locked Goal & Metrics objective). Runs stay in Project Chat, which holds the SSH approvals.
- Every write re-checks the chat's permissions before it happens, is limited per turn (to-dos 5,
  notes 3, papers 12, ideas 5, metrics 10), lands once per identical request, and is reported only
  from its receipt. Under "ask every time" each write shows a native confirmation naming what is
  added (`confirmingAssistantWrites`, which replaces `confirmingModelLabAdds`).
- The chat's to-do proposal cards gain the reviewed "＋ 할 일 추가" dialog, prefilled from the
  proposal (`chatTaskDraft`), next to the existing JSON export.

## Model Lab module detail: arrows, data flow and an AI explanation

User request: move between connected modules from the detail view (both directions) instead of
closing it and clicking the next card; explain in detail what each module does.

- The detail header has ← and → buttons (and the ←/→ keys): the previous and next connected modules
  of the graph being viewed; with several, a small menu lists them by name and tensor. The dialog stays
  open, the arrow keeps focus, and the body returns to the top.
- A "연결 흐름" section lists where the module's values come from and go, with links to those modules.
  Inside an expanded loop the steps are read as statements (`moduleDataFlow`): a value comes from the
  last earlier step that wrote it, else from the previous iteration or the block's input, and goes to
  the later steps that read it before it is rewritten, else to the next iteration or the block output.
  Other graphs use their connections.
- A loop step also shows its repeated block's own notes and equations ("상위 반복 블록").
- "AI로 자세히 설명" asks Model Copilot (the model and account selected in Model Lab) to explain the
  module's role, symbols, shapes and data flow for the author, without proposing edits
  (`explanationOnly`: an edit in the answer is never staged). The question and answer also appear in
  the Copilot conversation. The answer is saved with the project's Model Lab workspace
  (`gosu.model-lab.module-explanations.v1`, keyed by the module's id and a digest of its statement and
  equation, bounded) and shown on later openings with "다시 설명". Failures are shown in the section.
