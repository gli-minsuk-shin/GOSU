## Chat: the context usage chip opens its details again

User report: "GOSU 에서 AI 비서나 project AI chat 에서 context 사용량 버튼을 눌러도 추가 정보가 안나옴."

Reproduced with the real component, the real ancestor chains and the real stylesheets in a browser.
Since 0.58.115 the details were `position: absolute; bottom: calc(100% + 6px)` against whatever
positioned ancestor the host happened to have:

| Host         | Containing block                                                                          | What happened                                 |
| ------------ | ----------------------------------------------------------------------------------------- | --------------------------------------------- |
| AI assistant | `.briefing-chat-input-box` (`overflow: hidden`; the chip moved into this box in 0.58.133) | laid out above the box, clipped away entirely |
| Project Chat | `.project-chat-shell.chat-file-drop-target` (`overflow: hidden`)                          | laid out 333px above the top of the window    |

`<details>` did open (the chip changed color), but nothing could be seen. 0.58.133 recorded that its
layout had not been checked in a browser.

- The details are a popover (`popover="auto"`): they open in the browser's top layer, which no
  container can clip, and the component places them from the chip's own position just before they
  are shown (`contextDetailPlacement`: above the chip when there is room, below it otherwise, never
  wider than the window, 8px inside it; repositioned on window resize). The chip is a button and the
  popover's declared invoker (`popoverTarget`), so the browser does the toggling, light dismiss and
  Escape, and a click on the chip cannot close and immediately reopen it.
- A popover takes the system text color unless it is given one, and the desktop has a dark theme:
  the panel and the chip now have `light-dark()` colors (Briefing Lab declares a light color scheme
  and looks as before).
- Model Lab mounts the same component and gets the same fix.

Seen in a browser (real component mounted live in both ancestor chains, 680px window): before, the
panel was not the element at its own center in either host; after, it opens 6px above the chip,
inside the window, is the element at its center, closes on a second click and reports
`aria-expanded` correctly. The first attempt was 26px too wide (the pixel width did not include the
padding): `box-sizing: border-box`, now part of the test.

## Usage: which models ran each feature

User request: "기능별로 쓰인 model 을 시각화 … 기능별로 어떤 모델이 쓰였는지 궁금함", then "기능 아래
모델별 누적 막대로 그려줘".

- Each feature row of "사용 분포" has its bar split into one segment per model, by the chosen metric
  (tokens or API-equivalent cost), and under it the models are named with their share, so the colors
  never have to be decoded. A model keeps one tone everywhere: the model list shows it as a small
  swatch and is the legend. Tones follow the report's model order, not the metric, so they do not
  change when the order does. Eight tones; red is left out because it means a warning here.
- A model without the chosen metric (no price, or no reported tokens) has no share: it is named
  last with "가격 미확인" or "—" and gets no segment. Shares are of what is known for the feature.
- The data was already there (`byWorkloadModel`, 0.58.138). `buildUsageDistribution` now returns the
  parts on each feature row; without a complete breakdown a feature keeps its plain bar.
- Found in the browser: a very long model id under a feature widened the list past its column. The
  list column is `minmax(0, 1fr)` and the name is cut with an ellipsis.

Seen in a browser (the real `UsageView` with example data, 680px window and zoomed out for the
two-column layout, light and dark): segment widths add up to the bar exactly, no horizontal overflow,
the unpriced model named but not drawn, a 97-character id ellipsized.

## Briefing: show only unread mail

User request: "Briefing Lab 에서 안읽은 이메일만 보는 버튼 넣자."

- "안 읽은 메일만" beside the history search. Pressed, every email section shows only the mail that is
  still unread: unread when the briefing read it from Mail (`mailUnread`, stored since the read-state
  work) and not marked read from GOSU since (`mailMarkedReadAt`). The heading reads "이메일 · 안 읽은
  2 / 5개", the highlights and the section count follow the filter (a highlight must not point at a
  hidden card), and a briefing without unread mail says so.
- It is a display filter over saved state: Mail is not asked again (a live check is one `osascript`
  per message and asks for approval each time). The button's tooltip says which moment the state is
  from. A mail whose state was never recorded (briefings saved before the flag existed) is hidden
  too and counted in a note, so nothing disappears silently.
- Not kept between visits: a forgotten filter would silently show a fraction of a briefing. Not
  offered when the history holds no mail. The "읽지 않은 메일만" collection setting is unchanged: that
  one decides what a briefing collects, this one only what is shown.

Seen in a browser (the real feed with the real stylesheets, filter on): pressed button, two of five
mails, highlights limited to them, the note about one hidden mail.

Regression tests: `context-usage-meter.test.tsx` (+3, and the existing case moved from
`<details>` to the chip and popover), `global-assistant-chat.test.ts` (the assistant's input box
still clips, the details are `position: fixed`), `project-chat-view.test.tsx` (chip and popover
markup), `usage-distribution-model.test.ts` (+2), `usage-distribution-ui.test.tsx` (+1),
`briefing-history-view.test.tsx` (+2).
