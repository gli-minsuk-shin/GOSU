## Briefing guidance list

User request: a button at the top of Briefing Lab for standing instructions the AI must consider when
it writes summaries, for example "always include mail from a given person or institution in the AI
briefing summary", edited as a list with add, edit and delete, one line at a time. The user chose
"LLM 지침 + 주소 고정": the guidance goes to the model, and a mail address or domain written in a line
also pins that mail deterministically.

### Storage

- `BriefingGuidanceStore` keeps the lines per routine in its own sealed file,
  `briefing-lab/guidance.v1.enc.json` (AES-GCM with the Briefing system key, like the other Briefing
  stores). It is not part of the routine profile, so an edit never changes `generationRunDigest` or the
  schedule digest (no automatic-briefing pause), settings saves cannot drop it, and an older GOSU
  ignores the file.
- A line is one normalized line of 1–300 characters; at most 20 lines per routine. A line that looks
  like a password, API key or token (`secretPattern`) is refused.
- Routes: `/assistant/guidance/list`, `/add`, `/edit` and `/delete`, each returning the whole list.
  Each rejection has its own Korean message (`briefing_guidance_text_invalid`, `_secret`, `_limit`,
  `_not_found`, `_unavailable`), and an unreadable file stops the summary with
  `briefing_guidance_unreadable` instead of silently summarizing without guidance.

### Use in summaries

- The email and paper summaries (`analyzeBriefing`) and the quick first briefing receive
  `userGuidance` (the lines) and an added instruction: apply matching guidance to importance,
  importanceReason and emphasis; guidance never creates facts, deadlines, actions or items, never
  changes the schema or the evidence and quote rules, and never authorizes tools. Without guidance the
  prompt and instructions are unchanged.
- `src/briefing-guidance.ts` reads mail addresses and domains from the lines (ASCII runs, so a Korean
  particle ends an address) and matches a sender's header address exactly or by domain and subdomain,
  never by display name. A matching email is sent with `matchesUserGuidance: true`; in the quick
  briefing it is kept even beyond the newest-80 metadata cap.
- "먼저 확인할 내용" puts mail from a listed address or domain first (up to 5, labelled "지침"), then
  fills the usual three email slots; the history view reads the guidance and updates after each edit.
- Guidance applies to newly summarized mail and papers; existing summaries and the summary cache are
  unchanged.

### Interface

- A list icon with the line count sits first among the "개인 연구 브리핑" header buttons. It opens a
  panel with the numbered lines (each with 수정 and 삭제, editing in place), an input with 추가, the
  count out of 20, and the server's reason on a failure. Lines with an address or domain show
  "… 메일 고정". If the list could not be read, opening the panel reads it again and shows the reason
  when that also fails.
- The panel is placed against the header's right edge (the control is `position: static`), so it
  stays inside the window at every width. It uses no `<p>`: the compact header hides `p`, which would
  have hidden the loading, empty and error lines.
