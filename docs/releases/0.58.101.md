## Count everything since the last briefing, never wait on server downloads, warn on every miss

User decisions: keep the date-bounded search; read every email since the previous briefing, count
them, summarize only the configured maximum and carry the rest to the next briefing; do not wait for
bodies Mail must still download from the server; add safeguards so missed mail is at least reported.

The mailbox list itself is local and already fast (0.58.100). The slow parts were Mail's own search
over the 117k-message Gmail mailbox and bodies not yet downloaded (up to about 61s each).

Changes:

- Overflow is counted, not truncated silently: after the per-run limit the reader keeps checking the
  remaining newer messages cheaply and reports `pending` (and whether counting finished). Coverage
  stays at the last loaded message, so the next briefing starts there. The mail note says
  "새 메일 N통 중 M통 요약 대상 · 나머지 K통은 다음 브리핑에서 이어서 요약".
- Bodies are read in a separate, supervised step (`runAppleMailBodies`). The ordinary read returns
  after metadata and links (`bodiesDeferred`); a bodies action announces each message
  (`body-start`), reads its body and a size-guarded source proof by id. If a message produces nothing
  for 8 seconds (20 seconds before the first), that reader is stopped, the message is recorded as
  unavailable and a new reader continues with the rest, within 120 seconds overall. Mail keeps
  downloading in the background; the next briefing reads that body again.
- Every miss path now produces a user warning, with its reason: a mailbox read that failed (also when
  another account succeeded, which previously appeared only in the note) or returned a partial result
  without coverage; new mail over the limit (with the count); bodies still downloading (with the
  count); an incomplete read or unordered mailbox; an interval that aged out of the days window; a
  failed AI summary batch; and a failure to save coverage.
