## Overlapping header and "routine_busy" in the Briefing view

User report (screenshot, 0.58.116, while a briefing was being generated): the progress box beside
"개인 연구 브리핑" ran under the guidance and collapse buttons, and the page showed "브리핑 지침을 읽지 못해
지침 메일 고정을 적용하지 못했습니다. routine_busy".

### Header overlap

Reproduced with the real components and stylesheets: with the paused-schedule warning and the running
progress beside the title, the progress text ran past its box by 12 px at an 820 px body, 72 px at
700 px (about the screenshot's width) and up to 152 px at 480 px. In the title slot only the stage name
could shrink; "11/57개 저장" and "경과 …" never shrank and the line did not clip, and the slot's 160 px
minimum could exceed a narrow title column.

- The progress line clips its content; the stage name gives way first, then the elapsed time, and the
  saved count does not shrink. The full line is the summary's tooltip.
- The collapsed warning shrinks before the progress (it opens for its full text), keeps a 62 px minimum
  for a "!" mark and its chevron, and its tooltip now carries its text.
- The slot's minimum is `min(160px, 100%)`, so it can never be wider than the title column.

### routine_busy

The Briefing Lab server serves at most three concurrent requests and answers a fourth with 429
`routine_busy` before reading it (`briefing-server.ts`). Since 0.58.112 the header's guidance button
and the saved briefing view each read the guidance, on top of the history, generation status and
chat requests, and one read was turned away; the view printed the raw code.

- `sourceRequest` sends a request refused as `routine_busy` again after 0.3, 0.7 and 1.5 s (the server
  had done nothing with it), stops when the request is cancelled, and after the last try reports "Briefing
  Lab이 다른 요청을 처리하는 중이라 … 잠시 뒤 다시 시도해주세요" with the code kept on the error. The
  conversation restore reads that code.
- The guidance button and the saved briefing view share one read per routine (`readBriefingGuidance`);
  a finished read is not reused, so saved changes are always read again.
