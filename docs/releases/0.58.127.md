## The routine's delivery times finally run the briefing

User question: does setting a time brief every day or week at that time? It did not. The routine
editor's frequency, interval, weekdays and "전달 시각" only fed the displayed "다음 일정" preview
(`nextOccurrences`); the only thing that ran anything was the "자동 브리핑" interval (every N hours
from the moment it was chosen). The user asked for the routine's times to actually run, with the
interval still refreshing the briefing in between.

- The automatic-run record now also keeps the routine's own schedule (`routineSchedule`), and
  `nextGenerationDueAt` picks whichever comes first: the routine's next delivery time or the saved
  interval. Both may be on at once — for example 08:00 and 18:00 plus every 4 hours.
- A delivery time that passed while the Mac was asleep or GOSU was closed is already behind the
  present, so the next check runs once and moves on; missed times are not replayed one by one.
- The Briefing header gains a "루틴 시각 (08:00, 18:00)" checkbox beside the interval, shown only for a
  routine that has delivery times. Ticking it saves that exact schedule; editing the times in settings
  updates the saved schedule once, without another click. The header stays compact: the next run is in
  the tooltip, not a new line.
- Automatic runs keep every existing rule: they need the routine's approval with "항상 허용", they pause
  with the same message when the approved scope changes, and turning both the times and the interval
  off stops everything.

## Model Lab: asking follow-up questions inside the module detail

User request: after the AI explains a module, be able to ask and answer there, through Model Copilot,
without leaving the module detail box.

- The "AI 설명" section is now a discussion: the first explanation, then a question box in the dialog
  itself. Each question goes to the same Model Copilot conversation (so it is also in the Copilot
  panel and keeps the model's context and memory) with this module's identity, source, equation, data
  flow, repeated block and the last exchanges attached, so a short question still lands on the module.
- Answers appear in the dialog as they arrive; the box locks while Model Copilot answers, a failure is
  shown in place, and a question that could not be sent returns to the box instead of disappearing.
- The discussion is saved with the model (`gosu.model-lab.module-explanations.v1`, at most 20 messages
  per module) and shown again when the module is reopened. "다시 설명" starts it over. An earlier saved
  single explanation is read as the first answer of the discussion.
