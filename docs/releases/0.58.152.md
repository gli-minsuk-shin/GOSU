## 논문 요약 AI is its own chat

User report, twice: "논문 요약 AI 를 AI 비서랑 따로 분리한다고 하지 않았나? 이러면 AI 비서에서
이야기 하던거랑 논문 요약 AI 가 섞여서 나중에 AI 비서 쓰고 싶을 때 쓰기 어렵잖아?" and then
"GOSU 논문요약 전용 AI chat 이 AI 비서랑 구분이 안가잖아??? 이거 왜이래?"

0.58.147 gave the role its own model and 0.58.148 made a paper turn use it, but the conversation
itself was still the AI 비서's: a question about a paper was appended to the assistant's transcript
and shown in its pane. The model was separate; the chat was not.

- **Stored apart.** A turn about a paper is kept under that paper's own conversation scope. The
  assistant's transcript holds only what was asked of the assistant.
- **Shown apart, which is where it actually went wrong.** `conversationDisplay` flattened every
  conversation of a routine into one list, so separating the storage alone would have changed
  nothing the user could see. It now returns one chat. What it kept is the older behaviour that
  matters: an owner may still read their own earlier chat after the routine's permissions changed,
  because a chat is matched across permission scopes, not by one exact scope.
- **Its own place.** The conversation opens as a panel inside 논문 요약, under the paper it belongs
  to, with the paper's title in the header and a line saying it does not mix with the AI 비서 and
  which model role it runs on. The chat is the same component as the AI 비서, so it has the same
  design and the same behaviour, which is what the user asked for originally.
- A paper card's "AI 질문" button now goes there instead of opening the AI 비서 pane with the paper
  attached, which is what mixed the two in the first place.

## A paper's conversation is the paper's, not the briefing's

User report: "논문 요약에서 AI 질의응답하고, 논문 요약 update 했는데, AI 질의응답한 논문이 0개
라네."

0.58.149 recorded a conversation on the shared paper library's own record. In the reporter's library
101 papers are listed and exactly **three** are such records; the other 98 come from briefing
history and had nowhere to be recorded, so the count stayed at zero.

- `paperConversationKey` names a conversation by the paper: its versioned arXiv id, else its own web
  link reduced to host and path, else the library record, else the item it was opened from. The same
  paper reached from two different briefings is one conversation.
- The 논문 요약 list reads its counts from the conversation store, so a paper from a briefing counts
  exactly like a library record. The mark on a row shows how many turns and the last question.
- The count spans permission changes, so it does not reset under the user.
- `sourceUrl` on a paper chat reference is accepted only as `http`/`https`. It comes from a card and
  names a conversation; `file:`, `javascript:` and `data:` have no business there, and there is a
  test for each.

## Removed: the library record's own conversation note

0.58.149's `noteConversation` wrote an excerpt of each turn into the sealed library record. With the
conversation store holding the real thread for every paper, that was the same thing in two places
and it only ever worked for the three records. The chat no longer writes it, and its warning is
gone; the optional field stays in the schema so records written by 0.58.149 still parse.

`SharedPaperSummaryLibrary.noteConversation` itself is still defined, with its own test, and is now
called by nothing — the bundle check found the name still in `app.asar`, which is how this was
noticed. It is dead code, not a second write path. Removing it is the first commit of 0.58.153
rather than a re-run of a pipeline this build already passed.
