## 논문 요약 and 논문 분석·질의응답 are two roles now

User request: "AI Agent 설정에서 '논문 요약 AI · 논문 분석과 논문별 질의응답'이 같이 묶여 있는데,
두개를 서로 다른 모델이 쓸 수 있게 하자. 왜냐하면, 논문 요약은 간단하고 대략적인 논문의 내용을
빠르게 요약하는게 목적이라면 (빠르고 저성능 모델이 더 맞음), '논문 분석과 논문별 질의응답' 는 매우
심도 깊은 연구 논의가 이루어져야하기 때문에 고성능 모델이 필요함."

- Settings → Agent has two rows where 0.58.147 had one:
  - **논문 요약 AI · 논문 내용 빠른 요약** — the pass that turns a paper into a saved summary.
  - **논문 분석·질의응답 AI · 논문별 심층 논의** — the per-paper conversation.
- Each takes its own 고성능 / 빠른 / 가장 빠른 / 기존 설정, so a quick summary can run on the
  cheapest model the user owns while the conversation runs on the most capable one.
- The two fall back differently, which is the part that matters most until the user sets them.
  Summarizing follows the **Briefing** role, where bulk summarizing is already tuned. The
  conversation follows the **전역 AI 비서** role, because that is the model the user talks to. A
  shared fallback would have sent deep questions to whatever model was chosen for getting through
  mail quickly, silently.
- `usageChoice` is still the one place that answers which role a usage runs on, so
  `briefingChatUsage(aboutPaper)` no longer needs the policy at all: a paper turn asks for
  `paperChat` and everything else for `briefingAssistant`, and the fallback is decided in one place.
- Nothing changes for a stored `model-routing.v1.json` that has neither role set, and a file that
  already sets 논문 요약 keeps that model for summarizing. The new role starts unset, so the
  conversation keeps running on the assistant's model exactly as it did in 0.58.148 and 0.58.149.
- Ingestion is untouched: `paper-summary-ingestion.ts` still asks for `paperSummary`.
