# GOSU 0.58.88 installed; in-app Claude subscription login

See [Claude Code login service](../../apps/desktop/src/main/claude-code-login.ts) and
[release procedure](../RELEASE_RUNBOOK.md). Includes pending 0.58.87 generation deadlines.
Cumulative dirty source (Git HEAD `303360b`); no commit/push.

Diagnosis: `claude auth status` reported a logged-in claude.ai subscription while every native turn
returned HTTP 401 for an expired OAuth access token. Status output does not validate token expiry, so
Claude appeared connected but Project Chat only showed the generic provider failure.

Changes:

- Project Chat keeps the stable `codex_unavailable` attempt code but shows actionable copy for
  `claude_code_auth_required` ([service](../../apps/desktop/src/main/project-chat-service.ts)).
- Settings → AI 연결 → Claude adds in-app `Claude 로그인`. Main runs the official
  `claude auth login --claudeai` with the sanitized provider environment. Claude Code opens the
  browser and keeps the credential in its own storage; GOSU receives only the process outcome and
  may reopen only an HTTPS claude.ai/claude.com/anthropic.com sign-in URL printed by the CLI. One
  login runs at a time, with cancel and a ten-minute timeout. Success enables or refreshes the
  Claude connection. No API key fallback.
