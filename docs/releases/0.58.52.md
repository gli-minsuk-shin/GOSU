# GOSU 0.58.52 installed

See [Briefing workspace](../BRIEFING_WORKSPACE.md) and [release runbook](../RELEASE_RUNBOOK.md).

Emails use importance first, then newest received time within each existing triage bucket.
Summary creation/reuse timestamps do not reorder mail. Live lists, stored History and top email
highlights follow the same rule; paper lists retain their existing ordering.

Sender header metadata is saved in encrypted History and displayed compactly with receiving account
and receipt time. Names are abbreviated visually with the complete From header in a tooltip; no
sender is inferred from a subject, summary or receiving account. Long metadata uses ellipsis, not
extra blocks. Existing histories lacking senders show an inline explicit header-recovery action
when the original message is resolvable. It reads only that message's From header, preserves read
status, does not invoke an LLM, and stores the recovered metadata. No automatic mailbox-wide
backfill runs on render. Existing ownership, account, RFC ID/native ID and permission guards apply.
