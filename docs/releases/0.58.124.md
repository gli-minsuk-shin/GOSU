## Model Lab: dragging the graph drew a selection box

User report: dragging the Model Lab graph to move it drew a selection rectangle instead.

React Flow turns a canvas drag into box selection whenever it believes Shift is held (`selectionKeyCode`
default `'Shift'`), and it tracks that from key events on the Model Lab window, so a Shift whose key-up
it never saw keeps every later drag in selection mode. Reproduced in a built preview: with Shift
registered, a drag drew the rectangle and left the pane in selection mode; without it, a drag moved the
graph. Model Lab has no use for box selection.

- `MODEL_GRAPH_POINTER_OPTIONS` (`panOnDrag: true`, `selectionOnDrag: false`, `selectionKeyCode: null`)
  is spread into the graph: a drag always moves the graph. Clicking a card still opens it.

## Model Lab: loop steps showed no equation and no explanation

User report (screenshot of "Repeat Step Abcd Block 2" from the model the project chat added): the
detail showed "Equation not deterministically derived from step 2" and an explanation that only
repeated the code.

Steps inside an expanded for-loop come from the block's `do:` lines. Only a fixed set of exact
operation patterns (Linear, GELU, FiLM, RMSNorm, soft-threshold, …) produced an equation and a name;
any other line got the placeholder, the name "Custom operation · step N" (shown as the id-derived
"Repeat Step Abcd Block N") and the explanation "Operation inside one … iteration: <code>". In the
chat-added ABCD model all 17 steps were like that.

- `repeat-step-description.ts` reads one pseudocode statement (assignments, `;`-separated pairs,
  tuple targets, `+=`, `->`, calls, keyword arguments, slices, powers, `...`, `if/elif/else/while/with`
  headers) and transcribes it to LaTeX literally: every operand kept, nothing inferred; for example
  `q\leftarrow \operatorname{q\_proj}(\operatorname{norm\_b}(B))\cdot \exp(\mathrm{log\_temp})`.
  Exact operation patterns still win; text that is not code keeps the explicit placeholder.
- Step names come from the statement: "Compute q", "Residual update B", "Update B, C",
  "If l in 0..6", "Pass C as C_final".
- The explanation follows the application language, one sentence per line: what the step computes or
  updates and the calls in computation order with their role (정규화, 선형 투영, 혼합, 어텐션 …), the
  operators, the values it reads, a note when part of the source is elided as `...`, the enclosing
  `if`/`with` it runs under (tracked by indentation), its position in the loop and the author's `#`
  annotation. The detail keeps the line breaks (`white-space: pre-line`).
- Previous tests that pinned the placeholder for code the literal reading now covers
  (`H3 = GELU(H3) + b`, `soft_threshold(H1, learned_threshold(H2))`, `7 * tanh(H / 5)`) now expect the
  literal equation, which keeps every operand (no narrower GELU-only or saturation form).
