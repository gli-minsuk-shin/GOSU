## No login password prompt after every update

User report: GOSU asks for the Mac login password at every launch.

Cause: at startup `LocalDatabase.open()` decrypted `local-key.bin` with Electron `safeStorage`, which
reads the Keychain item "@gosu/desktop Safe Storage". GOSU is signed with a local certificate
(`TeamIdentifier=not set`), so macOS binds a Keychain "Always Allow" to the exact build and asks
again after every update; many updates in a day made it appear on every launch. The Briefing memory
key, read by the small Keychain helper in `GOSU/briefing-lab/runtime` (built once, not part of the
app bundle), was checked on the same Mac: it returned a 32-byte key in 0.02s without a prompt.
Chromium cookie encryption is disabled by the Electron fuse, so it does not read that Keychain item.
The lecture manifest and Overleaf credential stores still use `safeStorage`, but only when those
features are used, not at startup.

Change: `resolveLocalDatabaseKey` wraps the database key (AES-256-GCM) with a key derived by HKDF
from the Briefing system key and stores it as `local-key.v2.json`. Startup opens the database with
`openWithKey`:

- Existing installations read `local-key.bin` through `safeStorage` one last time, open the database,
  and only then write the wrapped key. `local-key.bin` is kept so an older build still opens.
- Later launches use the wrapped key and never call `safeStorage`.
- A new installation creates a wrapped key directly.
- If the helper is unavailable, the legacy path is used as before; a wrapped key that fails to open
  the database is re-migrated from the legacy key; a wrapped key that cannot be read with no legacy key
  is never replaced.
