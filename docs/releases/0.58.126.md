## Phase 3 of "every chat can reach everything": Project Chat reads calendar, mail and briefings

User report: a Project Chat answered "저는 Board만 볼 수 있고 개인 캘린더는 볼 수 없습니다" and asked
that Project Chat reach the calendar, email, Briefing Lab and paper summaries. It had no path to
them: the Briefing reads all require the browser client token that owns the routine, which the app's
own Main process never has. The user chose that every project chat gets this automatically, following
only the Briefing Lab settings, with no separate per-project switch.

- `BriefingWorkspaceStore.hostReadProfile` / `assertHostRead` / `hostPrivateAllowed` are the app's own
  trust boundary: the GOSU app reading on the user's behalf has no client token, so ownership is
  replaced by the app itself while the saved approval, scope digest and per-permission flags still
  decide. Calendar needs calendar reading and at least one selected calendar; mail needs mail reading,
  private AI use and a saved mailbox scope; private briefings and paper summaries need private AI use.
- `createBriefingHostReads` (`briefing-host-reads.ts`) holds the policy: pick the approved routine,
  confirm first when its policy is "ask every time" (the dialog names the calling project chat),
  perform the read through the existing Briefing paths, re-check the routine afterwards, and return a
  bounded result (30 events, 6 messages of 1,800 characters, 6 briefings or one full record, 6 paper
  summaries or one full five-section summary) marked as untrusted personal content. `LiveSourceService`
  supplies those paths and `BriefingDesktopHost.reads()` hands the object to Main.
- Project Chat gains four read-only tools — `read_calendar`, `search_email`, `read_briefings`,
  `read_paper_summaries` — offered on every ordinary turn (never in a Critical Review) whenever the
  Briefing host exists. A permission that is off returns its exact code, so the chat names the missing
  Briefing Lab setting instead of claiming it cannot see calendars. Policy version 42 states the scope,
  the read-only rule and the untrusted-data rule; the capability line now reads "보드 / 할 일 + 목표 +
  Briefing 일정·메일·브리핑·논문 요약 읽기".
- Nothing writes: no event, reminder, mail send or read-marking is possible from Project Chat, and the
  saved mailbox, lookback and calendar selection can only be narrowed by a query, never widened.
