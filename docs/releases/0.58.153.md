## Pressing "AI 질문" on a paper card opened nothing

0.58.152's own bug, reported the same day: the card navigates to 논문 요약 and asks for that paper in
the same pass, so the screen mounts and receives the request together. React runs effects in
declaration order, and the request was synced in an effect declared _before_ the routine effect that
clears the open conversation on mount — so it was set and then wiped a moment later, and no panel
appeared. Moving the sync after that effect fixes it. The row's own "AI 질의응답" button was never
affected, because the screen is already mounted when it is pressed.

Checked against the bug: restoring the old order fails exactly the new test and nothing else.

## AI 비서 and Project Chat can read a paper's conversation

User request: "AI 비서랑, Project AI chat, Model assistant AI 에서 논문 요약 AI 의 대화 내용과
논문요약 session 에 접근해서 작업할 수 있게 하고."

Read only, in both. Answering in either of them never adds to a paper's conversation — that is what
0.58.152 separated — and every answer carries a line saying it is continued in 논문 요약.

- **AI 비서**: `list_paper_conversations` names the papers that have one, newest question first, with
  how many turns each has and its last question. `read_paper_conversation` takes the `historyId` and
  `paperId` those return and gives that paper's thread.
- **Project Chat**: one tool, `read_paper_conversations`. With no arguments it lists; with a
  `historyId` and `paperId` it reads. It goes through the Briefing host's read bridge, which grew
  from four readers to five, under the **same permission as the paper summaries** — a conversation
  is the user's own questions about those same papers, and a separate gate would only ask them to
  allow the same thing twice.
- A paper with no conversation is a named refusal (`assistant_paper_conversation_unknown`), not an
  empty answer.

### A conversation remembers its own paper

The first version joined the conversation index against the saved paper library, and a test came
back with an empty list: a paper that is not in the library has a conversation nobody could name.
Removing a briefing would have hidden the conversation about its paper. Each conversation now
records the paper it is about — ids, title and the key it is stored under — so the list stands on
its own.

### Not Model Assistant, and why

Model Lab's assistant has seven tools, all of them about model structure, and **no bridge to
Briefing at all**. Until now the direction has been the other way: AI 비서 and Project Chat read
Model Lab. Reaching Briefing from there means opening a new cross-app permission surface, which is
worth designing on its own rather than adding to the end of this change. The user chose to ship the
two that exist and decide about the third after using them.

## Removed: `SharedPaperSummaryLibrary.noteConversation`

0.58.152's bundle check found it still in `app.asar`, called by nothing, and its record said it
would go in the next release. It and its test are gone; the conversation store is the one place a
paper's conversation lives.
