## Model Assistant can read a paper's conversation

0.58.153 shipped this for AI 비서 and Project Chat and stopped there, because Model Lab had no
bridge to Briefing at all. The user asked for the third one next: "Model Assistant까지 하고
한 번에."

Model Lab's assistant gets one tool, `read_paper_conversations`, the same shape Project Chat has.
With no arguments it lists which papers have a 논문 요약 AI conversation, how many turns each has
and its last question. With an exact `historyId` and `paperId` it returns that one conversation.

### The permission is the one the user already granted

Model Lab adds **no permission of its own**. The read goes through the Briefing host's
`paperConversations` reader, under the **papers** permission of a Briefing routine — the same gate
AI 비서 and Project Chat pass, and the same "ask every time" confirmation, which now names the
caller as `Model Lab AI(프로젝트명)`.

Nothing else was opened. Mail, calendar, saved briefings and the paper summaries themselves stay
closed to Model Lab. A conversation is the user's own questions about papers; the rest of Briefing
is a wider grant than what was asked for, and it can be decided separately if it is ever wanted.

Read only, like the other two. Answering in Model Lab adds nothing to a paper's conversation, and
the instructions say so in the same words: it is continued in 논문 요약.

### The bridge, and why the tool can be absent

The app composition root passes the reader into `createModelCopilotMiddleware`; the standalone Model
Lab dev server passes nothing. When the reader is absent the tool is **never registered** rather
than registered and refused, because a tool the model can see is a promise to the user. The same
flag decides whether the instructions mention it and whether the context budget counts it, so the
turn's plan and the turn agree.

Registration does not depend on the permission, only on the bridge — exactly as Project Chat's five
Briefing tools behave. A user with no paper permission gets a named refusal on the call.

### A refused read now says what to do

Model Lab's tool receipts were a bare error code. The failures that arrive from outside Model Lab
are not codes the assistant has ever seen, so each one now carries a hint: that saved paper reads
are turned on for a routine in Briefing Lab and nothing in Model Lab can widen that, that an unknown
`historyId`/`paperId` should be looked up by listing first, that the user declined, that the
permission changed mid-read, that the read was cancelled.
