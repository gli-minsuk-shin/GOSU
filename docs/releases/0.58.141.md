## Literature search: what the user saw, and why

User report with a screenshot of the Literature tab: the text "TabPFN 클래스 확장과 관련된 논문 찾아줘.
라벨 임베딩 확장, … 정리해줘" produced "Semantic Scholar Unavailable", "0 core, 0 rising, 50 broad",
38 papers added, an English notice, and "초록 자동 분석에 실패했습니다. AI 정리를 사용할 수 없습니다."

Causes, each confirmed in the code:

- The text went to Semantic Scholar, Hugging Face Papers and Crossref exactly as typed. These
  indexes match English keywords; they cannot read a sentence or Korean.
- GOSU calls Semantic Scholar without an API key (the key is only read from an environment variable,
  which an app started from Finder never has). That public rate limit answers 429 often. One 429 on
  the first request dropped the whole provider with no retry, and with it every citation signal, so
  nothing could be Core or Rising.
- The ranking had no check that a paper is about the query. Relevance was only the provider's rank
  position, so rank 1 of an unrelated pool scored 1.0, and Broad was topped up to the requested 50.
- All three provider failures collapsed into one label, and the notice was an untranslated template
  with Title-Cased codes.
- After a search the view asked the model to organize the first 50 papers of the whole table that
  had no AI draft, in one turn with a 120 second limit, and reported every failure (timeout, a turn
  the provider ended, a thread that could not start) as "AI organization is unavailable".

## Literature search: changes

Ranking policy version 4 (`BALANCED_LITERATURE_POLICY_VERSION`):

- `literatureQueryTerms` turns the search text into topic words (no request or filler words, Korean
  particles removed, at most 24). A paper is kept only when its own title, abstract, provider topics
  or venue mention them: one term for a query of up to three terms, two from four terms on. A paper
  seen only in a citation-sorted or newest-first list must mention at least half of the terms,
  because those lists hold anything that shares a word with the query.
- The gate applies to every layer, including the citation-lane classics of Core.
- Broad is filled only from papers that pass the gate. A search can therefore select fewer papers
  than requested, or none. Without known terms a sorted-lane leftover is not saved.
- The Core and Rising gates did not change, so a version 3 label still means what the explanation
  says and is not shown as legacy (`BALANCED_LITERATURE_CORE_GATES_SINCE_VERSION`). Bumping the
  version had first marked every existing paper "Legacy policy v3"; a view test caught it.

Discovery:

- The Semantic Scholar relevance request is tried up to three times for `rate_limited`, `timeout`
  and `unavailable` (waits 1.5 s and 4 s, plus the provider's own Retry-After wait, abortable). A
  malformed response is not retried.
- The cause travels in the receipt as `providerFailures` (provider, cause, attempts). It is not
  stored: stored runs are parsed strictly, and a new value in the persisted degradation enum would
  make an older build refuse to open the library after a downgrade.
- "Insufficient Semantic Scholar results" now describes what was retrieved, not what survived the
  gate. Otherwise every narrow topic would call Crossref three more times and be labelled degraded.

Service and AI:

- A text without a topic ("논문 검색", "find papers") is refused before a run is recorded:
  `literature_query_without_topic`.
- `LiteratureAiService.runStructuredTurn` is the one tool-less turn runner for organizing and for the
  new `planSearch`. Its failures are `literature_ai_start_failed`, `literature_ai_turn_failed` and
  `literature_ai_timeout`; each has its own sentence that names Settings → Agent.
- `planSearch` turns a sentence, a question or non-Latin text into one to three English keyword
  queries with provenance tags. GOSU validates the answer itself: Latin script only, topic words
  present, not a sentence again, duplicates dropped. It uses the same model as AI organization (the
  `lecture` role of Settings → Agent through Codex); there is no new picker. The usage kind stays
  `literature_organize`.
- `undoSearchAdditions` removes papers that the given searches created (classified by the run and
  created at its completion time) and that nobody touched: no review status, no manual note. It
  uses the existing soft delete, so a later search can bring a paper back. There is no
  database-level test for Literature (the SQLite layer has none), so no new SQL was written.

View:

- A text that `literatureQueryNeedsPlanning` flags (non-Latin letters, a question, a request verb,
  nine or more words) is planned first; the planned queries run one after another and the notice
  lists them ("실제 검색어: …"). If planning fails, the text is searched as typed and the notice
  says why.
- Notices come from `literature-search-flow.ts` through the message catalog: counts, layers, the
  provider failure in words ("Semantic Scholar가 요청 한도를 넘었다고 응답했습니다 (3회 시도)"), and a
  separate sentence when nothing was selected. Degradation and signal labels are translated.
- Only papers this search created are organized automatically, ten per turn, at most thirty; the
  "organize next" button also works in turns of ten and keeps what succeeded before a failure.
- "추가된 N편 되돌리기" sits in the notice after a search that added papers.
- Buttons in a notice keep one line. Korean labels used to break per character ("닫" over "기").

## Project Chat: literature search on request

User report: "다만 현재 대화에는 GOSU Literature 검색·추가 도구가 제공되지 않아 …".

- The tool is granted per turn by `explicitlyAuthorizesLiteratureSearch`. It knew few Korean endings
  and read "문헌에서 … 논문 검색" as a lookup in the saved table. It now accepts everyday requests
  (twenty pinned phrasings, among them "관련 논문 찾아줄래?", "선행 연구 서베이해줘", "논문 검색",
  "We need to search the literature on …") and still refuses questions about the feature, reports
  of a past search, negations and lookups in saved data (ten pinned phrasings).
- When the tool is not granted, the prompt now says why (`literatureSearchCapability`: not requested,
  reviewer mode, library unavailable) and tells the model to show the user how to ask instead of
  calling the feature missing.
- The tool receipt lists up to twelve selected papers (title, up to three authors, year, layer,
  canonical URL from `LiteratureService.papersOfSearch`) and the `providerFailures`. A failed preview
  does not fail the already saved search (`papersUnavailable`).
- Policy text version 43: ranking version 4, English keyword queries with one query per sub-topic,
  reporting a dropped provider in plain words, and the link rule below. The fixed text shares the
  fallback context window with history; the characterization test now fits seven raw turns, not eight.

## Paper summary library

User report: the card "이 논문 분석을 Briefing Lab 논문 요약 보관함에 추가할까요?" failed with
"확인 가능한 논문 링크가 필요합니다" after a literature search in Project Chat.

- Cause: the card collected every safe HTTPS link of the answer, ingestion accepts only arXiv, DOI,
  OpenReview and PMLR links and rejected the whole save when one link was something else (here a
  link to a report section), and the papers the model named had no links at all.
- `verifiablePaperLink` in the contract is now the one rule, used by the card and by ingestion.
  The card offers only verifiable links. When the assistant offered the library but wrote no such
  link, the card says which links are needed and what to ask for, instead of failing on click.
- The card saves one paper per call, so each paper gets the library's full time budget and is
  committed by itself. It shows progress, lists the papers that failed with their reasons, and
  retries only those. Before, one 240 second budget covered up to twelve papers and one failure lost
  all of them.
- The chat policy tells the model to write every discussed paper as a markdown link in one of the
  accepted forms, from a tool result or web search, and never to invent a DOI, arXiv id or URL.
- BibTeX export in 논문 요약 (Briefing Lab): "BibTeX 내보내기 (N)" exports the selected papers, or the
  filtered list when nothing is selected, as `gosu-paper-summaries-YYYYMMDD.bib` through a browser
  download (the Lab runs in a sandboxed frame). Deterministic keys (first author family name, year,
  first title word, suffixes for collisions), `@inproceedings`/`@article`/`@misc` by venue, arXiv
  `eprint`, and verbatim `doi`/`url`/`eprint` so an underscore in a DOI still links. The year comes
  from the publication date only. The status line counts entries without authors or year.
- "논문 요약에서 불러오기" in the Literature toolbar lists the saved verified papers, related ones first
  (project name, recent searches and search tags matched against title, summary, keywords and tags;
  no model call), marks papers already in the table, and adds the chosen ones (at most 50) as
  imported records with their tags as search tags and the library summary as a note prefixed
  "[논문 요약 보관함]". No abstract is invented. Channels `gosu:paper-summary:list` and
  `gosu:paper-summary:import-to-literature` return bounded codes; the library is read again in Main,
  so the renderer names papers by id only.
- Found on the way: storage treats an `import` candidate as a review file and replaces the manual
  notes of a record it matches. `addFromAssistant` sent papers through that path, so an assistant
  naming an already annotated paper again would have cleared its notes. Every "add these papers"
  path now goes through `addImportedCandidates`, which leaves papers already in the table alone.

## Sidebar and notifications

- The group headers "프로젝트", "아카이브" and "숨김" used their own narrower grid and an 11px caption
  font, so they sat left of every row around them. All first-level rows now share one grid: a 22px
  slot for the 18px icon or chevron at the x of the Calendar icon, an 8px gap, then the label.
  Header text has the size and weight of the project names. "+" sits in the column of the row menus,
  the Archived count under the Projects count, archived names on the label column, and the child
  guide line under the chevron. Measured in a browser: icons at x=24 and labels at x=52 for the tool
  rows, both headers, project rows and archived names.
- "모두 읽음" in the notification panel is a bordered button in the accent color, one text size above
  the filter tabs, and stays readable when nothing is unread.
