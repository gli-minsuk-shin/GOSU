## Phase 1 of "every chat can reach everything": adding a model to Model Lab

User request (screenshot): a Codex Project Chat read a run's `RUN_CONTRACT.json` and answered that it
could not add the model to Model Lab ("Model Lab은 읽기만 되고"). The user asked that Project Chat, and
then the AI assistant chat, be able to reach everything. After a survey of both chats, the user chose
to proceed in phases (1: Model Lab add in both chats; 2: AI assistant writes such as real to-dos,
research notes, the project Literature library, manuscripts and experiments; 3: Project Chat reaching
calendar, mail, briefings and all to-dos) and that a requested write runs at once.

Why it was read-only: the only Model Lab write path lived inside the Model Lab iframe, and an open Model
Lab rewrites its whole workspace from memory, so a direct write from Main would be lost. The safe path
already existed for "Duplicate to project": a per-project copy inbox that an open Model Lab adopts.

- `ProjectModelTransferStore.addFromChat` validates chat-written GOSU Model Pseudocode with Model Lab's
  own parser (`model_lab_pseudocode_invalid: <reason>` on failure), refuses nested model references,
  keeps existing models (a clashing id gets a `-chat-<hash>` suffix), keeps the 64-model and inbox
  limits, and queues a revision-0 entry labelled "Added from project chat" / "Added from AI assistant".
  A replay of the same request id returns the same entry; a different model under that id is refused.
- `ModelLabDesktopHost.addModelForChat` queues it and waits up to 6 s for an open Model Lab to adopt it,
  returning a receipt `{modelId, modelName, status: added | queued}`. The Model Lab notice reads
  "Added N model(s) from chat." for these entries.
- Project Chat: `add_model_to_model_lab` is offered only for a turn whose own message explicitly asks
  to put a model into Model Lab (`explicitlyAuthorizesModelLabWrite`: names Model Lab plus an add verb,
  not a denial or a how-to question), never in Critical Review or legacy reviewer turns, and only for
  that project. It runs without a dialog, derives a request id from the attempt and the pseudocode (a
  retry adds once), allows four models per turn, and returns the parser reason on a validation error so
  the chat can correct and retry. Policy v41 lists it as a bounded exception.
- AI assistant: the same tool through the project bridge (`model-lab-add`), offered with the same
  explicit-request rule, requiring `projectRead` and private-AI approval; it runs at once under "always
  allow" and shows a native confirmation under "ask every time" (`confirmingModelLabAdds`).
- Both chats are told to report only the receipt (added now, or queued until that Model Lab opens).
