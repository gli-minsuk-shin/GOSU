# GOSU 0.58.21 — candidate

Fix new-event destination selection when the first configured calendar is read-only. The editor
chooses a writable calendar within the already allowed IDs, preserves a valid writable selection,
and never moves an existing event to another calendar. Loading/no-writable states disable submit
and display an explanation; the prepare handler also checks the destination before its API call.
See [Briefing contract](../BRIEFING_WORKSPACE.md) and [release procedure](../RELEASE_RUNBOOK.md).

Initial window inspection timed out; subsequent installed 0.58.20 UI inspection succeeded and
showed zero events with the explicit macOS Calendar access-required error. In addition to the
reproduced read-only selection defect, Calendar and the editor now offer direct OS reauthorization
and a trusted fixed-target privacy-panel shortcut. Reauthorization does not save/reset the
routine; an editor retry preserves the typed draft. No actual permissions or events were changed.
