## A Saturday dinner drafted on Sunday

User report: a mail about dinner with Linxia on Saturday was registered as a Sunday event.

Evidence (the local Claude Code transcript of that summary call, read without printing the mail): the
item was sent with `receivedAt` `2026-09-17T21:51:25Z` (Friday 2026-09-18 06:51 KST) and text that
mentions Saturday but gives no date. The model's prepared event was `2026-09-20T19:00:00+09:00`, a
Sunday (2026-09-19 is the Saturday), with evidence quote "See you soon on Saturday." and notice "정확한
시간과 장소는 추가 확인 필요". The briefing then used Haiku without thinking. GOSU checked the quote and the
time zone of the draft but never that the day matched the weekday its own evidence names, and the
"＋ 일정 생성" button reuses the saved draft without another model call, so the wrong day went straight
into the editor.

Change:

- `alignActionsToEvidenceWeekday`: when a draft's evidence quote (event) or deadline quote (task) names
  exactly one weekday (English or Korean, whole words only) and no explicit date, the draft is moved
  to that weekday by the shortest shift (at most three days), keeping the local clock time through
  Temporal (daylight-saving safe), and the notice says what GOSU changed. An explicit date, several
  weekdays or an all-day event leave it untouched.
- It runs where drafts are accepted (`screenInsights` before validation), in the separate
  `draftEmailEvent` job, and when a saved draft is opened from "＋ 일정 생성" or the task button
  (`alignedPreparedActions` on a copy, so summaries saved earlier are corrected when used, not
  rewritten).
- The prompt now also carries `receivedLocal`, e.g. "2026-09-18 (Fri) 06:51" in the routine time zone,
  and the instructions say a bare weekday means its next occurrence on or after that date, so the model
  no longer has to compute the weekday itself.
- "＋ 일정 생성" is offered whenever the summary prepared an event; the keyword check (마감, 회의, 약속,
  …) now only covers older summaries without a draft, which hid the button for an English dinner
  invitation.

The event already registered in the user's calendar is not changed by GOSU.

## A header warning that took the whole header (user request)

User report with a screenshot of 0.58.108: the "최근 브리핑 · …" warning filled the header next to the
title with every failed batch and its reason, the paused-schedule notice sat under it, and neither could
be minimized or dismissed.

Change: the run warning and the paused-schedule notice are now `<details>` that start closed. The closed
line shows the counts ("최근 브리핑 · AI 요약 4묶음 실패 · 요약 검증 실패 3개 · 메일 미확인 구간 4곳 · 메일 빠른 조회 불가",
ellipsized to the 420px column) or "자동 브리핑 일시 중지 · 설정 확인 필요"; clicking opens the full text,
limited to 40% of the window height with its own scrolling. The summary keeps `role="alert"`. The 420px
column rule also recognizes the new alert.

## What the warnings in that screenshot meant

- "AI 실행기가 요약을 시작하지 못했습니다 … (오류 코드: claude_code_failed)" for paper batches: the local
  Claude Code transcripts of the failed calls (08:28, 08:36, 12:58, 13:03–13:04 KST) end with ten
  retries of "Can't reach the API server — check your internet or DNS (ENOTFOUND)", i.e. the Mac lost its
  connection (DNS) to the Anthropic API while paper batches ran; the email batches had finished before.
  GOSU reported it as a login or CLI version problem. The adapter now maps that CLI result (ENOTFOUND,
  EAI_AGAIN, ECONNREFUSED/RESET, ETIMEDOUT, ENETUNREACH, getaddrinfo, "connection error") to
  `claude_code_network_unavailable`, the native runner passes the code through, and Briefing shows "AI 서버에
  연결하지 못했습니다. 인터넷(DNS) 연결 문제 …". The batch stays a warning and its items are summarized
  again by the next briefing.
- "요약 검증 실패" (0.58.105): items whose quote did not match after one correction; the rest was saved.
- "메일 미확인 구간" and "메일 빠른 조회 불가": new mail beyond the configured maximum waits for the next
  briefing, an interval older than the 3-day window is reported once, and without Full Disk Access Mail was
  read the slow way.
- The paused schedule: the approved scope changed (the AI provider/model settings were changed), so the
  interval must be selected again.
