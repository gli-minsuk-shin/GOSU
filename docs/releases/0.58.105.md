## Change (user choice: read Mail's index)

- `readMailIndex` opens the index read-only and returns message ids and received times of one
  mailbox, newest first: received after the window floor (the coverage `stopAt` when known, never
  below the approved days), not deleted, capped at 2,000 with the full count. Searches also bound
  `from`/`to`; a search whose window exceeds the cap uses Mail's query so its result stays exact.
- Mailboxes match by account id and decoded, NFC-normalized path; Gmail folders Mail shows without
  their `[Gmail]`/`[Google Mail]` prefix match with it; an ambiguous match is refused.
- The reader takes `indexed` ids instead of running `whose`: it reads each message through
  `messages.byId`, compares Mail's received time with the index (more than 2s apart throws
  `mail_index_mismatch`), and skips a message deleted since the index was read. Links, bodies, proofs,
  exclusions, limits, pending counts and coverage are unchanged.
- Fallback: a missing index, no permission, an unmatched mailbox or a changed schema, or a mismatch
  (retried once without the index), reads Mail the old way. The source result carries a Korean
  warning (Full Disk Access instructions when permission is missing), the generation adds it to its
  warnings and sets `mailIndexFallback`, and the header alert reads "메일 빠른 조회 불가".
- Only the real Mail reader uses the real index; injected test readers never touch `~/Library/Mail`.

The user grants Full Disk Access to GOSU in System Settings; GOSU cannot and does not change it. The
grant is bound to the app's designated requirement (bundle id and the fixed local certificate), which
update continuity preserves.

## Summary batches rejected after "사고 끔"

User report (header of the 23:25 run): "AI 요약 8묶음 실패", with reasons "한 차례 수정 후에도 인용
근거가 원문과 일치하지 않았습니다" and "AI 응답의 근거·항목·수식/그림 검증을 통과하지 못했습니다".

Evidence: the user had switched Briefing to the `lightweight` profile, Claude Haiku with `off`. The
ledger shows every 23:25–23:32 call succeeded (7–187s); GOSU's validation rejected the drafts. The
Claude Code transcripts of those calls (`~/.claude/projects/*gosu-routine-*`, inspected locally
without printing mail text) show three patterns: the model returned summaries for prior memory
entries as extra items (5 requested, 8 returned; every unknown id was a `memory[].sourceId` in the
prompt), quotes that matched only after normalizing typography, and paraphrased quotes. One bad item
rejected the whole batch of six, twice (draft and correction).

Change:

- `quoteMatches` compares evidence after NFKC, curly quotes/dashes to ASCII, collapsed spacing and
  case, and allows "..." between in-order fragments of at least four characters. Unsupported quotes
  still fail.
- `screenInsights` validates each item on its own: unrequested or repeated ids are dropped and never
  saved; an invalid prepared calendar event or task is dropped while the summary stays; an invalid or
  missing requested item is reported. `analyzeBriefing` corrects only the rejected items once, keeps
  the accepted summaries (overview from the kept draft), returns `rejectedItems`, and fails the batch
  only when nothing is usable.
- Memory entries go to the model as `{ kind, text }`, without ids that look like item ids; the
  correction instruction says memory entries are never items.
- The generation saves the accepted items, leaves rejected mail unhandled (so its coverage gap makes
  the next briefing read and summarize it again) and rejected papers unsaved, counts
  `summaryRejectedItems`, warns "…중 N통 요약 검증 실패 … 다음 브리핑에서 다시 요약합니다", and the
  header shows "요약 검증 실패 N개".
