## Every structured Claude turn was rejected by the CLI

User report on installed 0.58.94: Claude did not work at all; the Briefing AI assistant showed the
new message with `claude_code_failed`, and email summaries still failed in about 0.7s.

Diagnosis: direct CLI probes with GOSU's flags and environment succeeded, so the installed app's
actual invocation was captured once. With the user's run, the `~/.local/bin/claude` link was
pointed for a few minutes at a wrapper that recorded only runs whose parent was GOSU (and passed
`auth`/`--version` straight through), then restored to
`~/.local/share/claude/versions/2.1.272`; the log and wrapper were deleted. The captured run exited
1 with no stdout and stderr:

`Error: --json-schema is not a valid JSON Schema: no schema with key or ref "https://json-schema.org/draft/2020-12/schema"`

GOSU builds its output schemas with `z.toJSONSchema`, which declares the draft 2020-12 meta-schema.
Claude Code 2.1.169 accepted that; 2.1.272 (installed on 2026-09-16 03:22 KST) rejects it before
sending any request. Every Claude turn with an output schema therefore failed — Briefing summaries,
the Briefing assistant and Project Chat — while the probes had used schemas without `$schema`.
Reproduced deterministically: the same schema with the declaration fails, without it succeeds.

Change: `claudeCliJsonSchema` removes schema-level `$schema` declarations (a property that is merely
named `$schema` is kept) before `--json-schema`. The declaration carries no structure, and GOSU still
validates every result against its own schema. Model Lab's standalone Claude calls use hand-written
schemas without the declaration and are unchanged. A live repository turn with a zod-generated
2020-12 schema completed through the adapter.

## A paused schedule says why

User report: "설정 또는 권한 확인이 필요해 자동 생성을 일시 중지했습니다" did not say what to check. The
scheduler pauses when per-request confirmation is on, or when the approved scope digest (routine,
approved scope, mail scope, AI provider, mail read/AI transfer, calendars, to-do and project reads)
no longer matches. The usage ledger shows Briefing summaries moving from Codex to Claude Code on
2026-09-15, which changes that digest. Change: the pause message distinguishes per-request
confirmation, a changed approved scope (naming the items it covers) and a missing ownership or
saved settings. The record keeps only the digest, so the message does not claim which single item
changed.
