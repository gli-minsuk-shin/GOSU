## Briefing: mark all mail of a briefing read

User request: "daily 별로 briefing 에서 모두읽기 버튼 넣자. 하나씩 누르기 너무 귀찮다."

- Each briefing's email section heading has "모두 읽음 (N)" for the mail of that briefing that is
  still unread (saved `mailUnread`, not yet marked from GOSU, not marked in this session). It sits in
  a `<summary>`, so its click does not fold the section. Without unread mail there is no button.
- One request, `/mail/mark-read-all`, names the mails by saved history and item ids only (1 to 100).
  The server asks once under the ask policy ("이메일 N통 읽음 처리 …"), then marks one message at a
  time through the same single-message writer as the per-mail button: the single-mail route body
  became `mailItemAction`, shared by both routes, so every mail passes the same ownership, target and
  write checks. A mail that fails does not stop the rest; a mail already marked from GOSU is not
  written again. The answer is per mail, and each card follows its own result through the existing
  read-status listeners. The button then says "N통 읽음 처리 · M통 실패: <reason>".
- Cost: one `osascript` per message, as before. A single Mail script for many messages would be
  faster; it was not written, because the verified single-message script is the safe part.

## AI assistant: mail search is no longer cut to the briefing window

User decision: "메일 조회 범위가 5일로 정해져 있는데 … AI assistant 에서 제한 없이 검색해 달라면 검색할 수
있게 하자. 메일 조회 범위는 Briefing 만들 때만 적용하게."

- `resolveMailSearch` no longer clamps `from` to the saved days. The saved days stay the default of
  a search without `from`; an earlier `from` is searched as asked (floor 1990-01-01). A window wholly
  in the future is still `mail_search_outside_scope`. Accounts, mailboxes and the saved sender,
  subject and unread filters bound a search as before. This replaces the 2026-09-10 rule "these
  conditions narrow, never expand, the saved … lookback".
- The reason for the window was speed: a scripted `whose` query makes Mail check every message of
  the mailbox (2m20s at 93% CPU for the 117k-message mailbox). So a search wider than the briefing
  window runs only through Mail's index, and the index now narrows candidates by the search words
  itself: `readMailIndex` takes `terms` and joins `subjects` and `addresses` (`subject_prefix ||
subject`, `address || ' ' || comment`), confirmed against the real index schema (table definitions
  only). The result may hold more than Mail reports and never less: a term whose case SQLite cannot
  fold (non-ASCII letters with case) is left to the reader, which checks every message again.
- Without the index (no Full Disk Access, changed schema, unmatched mailbox) a wide search is refused
  with what to do (`mail_search_index_required`); more than 2,000 candidates ask for more words or a
  shorter period (`mail_search_too_broad`). A search inside the briefing window behaves as before,
  including Mail's own query when the index cannot answer.
- Under the ask policy a wide search is named once per turn, with its start date in the routine's
  time zone. The tool description tells the model that the saved days are only the default and what
  the two new failures mean; the old guidance "do not broaden" is gone. The setting is now labelled
  "브리핑 메일 조회 기간 (최근 일수)" with a tooltip saying it applies to briefings only.

## Usage: input and output per model instead of model cards; tabs for Briefing and paper summaries

User requests: "'모델 구성 · 모델별 사용량'은 사실 불필요함 … 사용 분포에서 model 별로 입력 출력 색깔 다르게
보여주면 되는 거잖아?" and "제일 밑에 Briefing 이랑 논문 요약 tab 넣자. 그걸 제일 많이 쓰잖아?"

- The "모델별 사용량" card section is removed. In "사용 분포" each model's bar is split into input
  (light green) and output (green) by the chosen metric, with a legend in the list heading, and under
  it: input, output, cache reads and calls. Money is split by `estimateUsageCostPartsUsd` (input side:
  plain input, cache reads, cache writes; output side: output, reasoning); `estimateUsageCostUsd` is
  now their sum, so the two sides add up to the row. "Priced as …" moved to the amount's tooltip.
  Green now means input and output only: the model tones of the feature bars no longer include it.
- Paper summaries are a feature of their own, `paper_summary`: `analyze()` records a paper-only
  batch under that kind (briefing batches hold one kind each). Earlier paper summaries stay inside
  "브리핑·요약"; nothing is reassigned or guessed.
- The report gains `byDayWorkloadModel` (optional, at most 1,000 rows): briefing and paper summary
  usage per local day and model, newest day first, under the same filters as the rest. The bottom
  tabs are now Briefing, 논문 요약, 프로젝트, 강의 생성, 제공자 및 모델, opening on Briefing; each of
  the two new tabs is a table by day and model with calls, input, output, cache reads, total and the
  API-equivalent estimate. An empty tab says why.

## Project literature search: findings only

User report: "Project 에서 문헌 검색도 문제가 많네 … 문헌에서 '논문 검색' 치니까 이상한 소리하는데?"
Investigated, not changed in this release. The card heading is "논문 검색" and the text typed under it
is sent verbatim to Semantic Scholar, Hugging Face Papers and Crossref; an empty Semantic Scholar
result silently falls through to Crossref, the Broad layer has no relevance floor and is filled up
to the limit, so unrelated Korean-language works are saved into the evidence table; the result
notice is an untranslated English template; AI organization then runs on those papers. Nothing on
the screen searches from the project's own ideas. Fixes are proposed for the next release.
