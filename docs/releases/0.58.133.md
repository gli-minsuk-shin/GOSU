## An email briefing failed again, and nothing said why

User report (19:2x): "이메일 briefing 또 실패 했는데? 왜 그렇지? 실패하고 난 뒤에도 logging 버튼 눌러도 왜 실패
했는지 message 도 안뜸... 이거 고치자".

What the local evidence shows for the run that started with GOSU 0.58.132 at 19:08 (nothing sealed was
opened; the unified log, file times and the usage ledger only): Mail answered every reader this time.
The mailbox list took 0.3 s and the saved-locations file (0.58.131) was written at 19:11:03; the reads
and body readers ran from 19:11:03 to 19:18:13 with no timeout and no Apple Event error; the briefing
stores were written at 19:18:14, one second after the last reader. Not one AI summary call was
recorded in the ledger after 15:00, and the Claude routine transcripts have no new file. So the run
ended right after collecting mail, before any summary.

The one code path that ends a run exactly there: `routedBriefingPreferences` threw
`model_routing_provider_permission_required` when the role model from Settings → Agent (Codex
`gpt-5.6-luna`, chosen at 11:02) was on another provider than the routine's Briefing provider
(Claude). In the batch loop that code matches `/permission/`, which rethrows and stops the whole run
at the first batch, so every email and paper stayed unsummarized. (I had noted this possibility in
the 0.58.130 report; it was designed as "never send private data to a provider the routine did not
approve".) The exact text of the failed job is in the sealed generation store, which this work does
not read; the user should see it in the header once the second fix below is installed.

- **Summaries run on the routine's own model instead of failing.** When the role model's provider
  differs from the routine's provider, `routedBriefingPreferences` now returns the routine's own
  preferences (its approved provider and configured model). Private data still goes only to the
  provider the routine approved. The run adds one notice (`roleRoutingNotice`): "설정 → Agent의 역할
  모델(Codex gpt-5.6-luna)은 이 루틴의 Briefing 제공자(Claude)와 달라 쓰지 않았습니다. … 역할 모델을 쓰려면 Briefing
  설정에서 제공자를 Codex로 바꿔주세요." The assistant chat's own provider guard (`briefing-assistant.ts`)
  is unchanged.
- **The header always shows a run's recorded reason.** `BriefingGenerationControls` showed the
  collapsed "최근 브리핑 …" line only for failed/interrupted runs and for completed runs with one of four
  counters (summary failures, rejected items, coverage gaps, index fallback). A completed run whose
  problem was an unread email source, a paper source that did not answer, or the routing notice above
  showed nothing. Now any `job.error` is shown, collapsed to one line: "최근 브리핑 실패", "최근 브리핑
  중단", or "최근 브리핑 · …" naming what is known ("이메일 조회 실패" when `emailSourceState` is `failed`,
  else "확인할 내용 있음").

Regression tests: `briefing-paper-cache.test.ts` (the fallback keeps the routine's provider and model,
the notice text, no notice without a policy or with the same provider), `briefing-generation.test.ts`
(+1: a scheduled run with all roles on another provider completes, summarizes on the routine's model
and carries the notice once), `briefing-generation-ui.test.tsx` (updated: a completed run's reason is
one collapsed line; +1: "이메일 조회 실패").

- **A test that every assignable model keeps the email summary working** (user request: "unit test에
  Briefing 이메일에서 모든 model이 working 하게 하는 거 간단한 거 넣자"): `briefing-generation.test.ts` runs
  the real daily generation for both Briefing providers × five role models (Codex `gpt-5.6-luna`,
  `gpt-6-astra`; Claude `claude-haiku-4-5`, `claude-sonnet-5`, `claude-opus-5`). Each of the ten runs
  must complete with no failed batch, summarize the fixture email, send it only to the routine's own
  provider, use the role model and reasoning when the provider matches, and carry the notice exactly
  when it does not. The fixture's model resolver now answers with the model it was asked for, as the
  real catalog lookup does.

## The paper-save offer no longer follows a question about a paper that is already saved

User report (screenshot): after asking about a paper the assistant itself said was already in the
library, the answer still ended with the card "이 논문 분석을 Briefing Lab 논문 요약 보관함에 추가할까요?".

The card is decided in the chat from the question and answer text alone (`paperSummaryCandidate`); it
never knew where the cited paper came from. Sources that the assistant read from the routine's own
paper library (`search_saved_papers` / `read_saved_paper`) now carry `saved: true`, and the chat
skips the offer when every paper source of the answer is saved (`answersFromSavedPapers`). An answer
that also read a new public paper keeps the offer, with only the new paper as its reference; an
answer with no paper source behaves as before. Tests: `src/briefing-chat-paper-offer.test.ts` (new),
`briefing-assistant.test.ts` (library sources are marked).

## The assistant chat gives its height to the conversation

User report (screenshot of the GOSU AI panel): "위에 AI chat box 공간 부분이 너무 작음 … 위아래로 좀 불필요한
공간 줄여서 넓히자. 너무 답답하다".

Around the conversation there were: a 40px header, a routine-name row, a "답변 완료" status row, a text
field fixed at 96px with its icons laid over its lower part, and under it a second row with the
context chip, the note "일정은 승인 후 실행 · 할 일은 연동용 초안" and the send button.

- The input box is one bordered box: the text area (`field-sizing: content`, two lines at rest, up to
  180px; 240px in the global assistant) and under it one toolbar row (`briefing-chat-input-toolbar`)
  with attach/think/settings on the left and the context chip, stop and send on the right. The row
  wraps when the panel is narrow and a turn is running. The separate button row is gone.
- The approval note moved to the send button's tooltip and stays readable for assistive technology
  (`briefing-chat-approval-note`, `aria-describedby`).
- "답변 완료" is still announced (`role="status"`, `data-quiet`) but takes no row; every other status
  (failures, "제안은 아직 실행되지 않았습니다", queue states) keeps its line, now 2px padded.
- The routine-name row is 3px padded; messages are 10×12px padded with 8px between them; the log's
  own padding is 8/10/6px. The global assistant gets the same box with its larger type.

Not verified in a browser: the briefing visual fixtures only run under the dev server, which cannot
start from this repository's folder in the preview tool, so this layout was checked by the component
tests (`briefing-chat-retention.test.tsx`: the context chip and send button are still in the form's
action row; a running turn shows no status row; completion keeps its status element) and by reading
the rules, not on screen.

## Usage: the page scrolls with the cursor over a table

User report: "사용량 session에서 scroll이 위아래로 잘 안 됨. cursor가 table 위에 있을 때는 scroll이 안 되네."
`.usage-table-scroll` is its own scroller (`max-height: 460px; overflow: auto`) with
`overscroll-behavior: contain`, which keeps the vertical wheel inside it, in current Chromium even
when the table is too short to scroll. It now contains only sideways overscroll
(`overscroll-behavior-x: contain; overscroll-behavior-y: auto`): a tall table scrolls first and then
hands the wheel to the page. Test: `usage-view-scroll-css.test.ts` (new).

## Model Lab: the "AI explained" mark, the explanation box, the sidebar

User requests: the AI-explained mark on modules is a green icon nobody notices; the AI explanation
must be inside the module explanation box again, not only in Model Copilot; the sidebar's model
sessions, graph import status and model selection should be adjustable and the "+ New / Import
model" button is too big.

- **Mark** (`module-node.tsx`, `--model-ai` violet, the one hue nothing else on a card uses): a filled
  violet tag "✦ AI 설명" in the top line and a 2px violet ring plus violet border around the whole card
  (`module-node--explained`), kept when selected and on collapsed loop blocks.
- **Explanation box** (`ModuleDetailDialog`): the saved Model Copilot explanation is the first block
  of "What this module does" (`module-detail-notes__ai`: title with the save date, follow-up
  questions as "내 질문", answers as Markdown), ahead of the automatic reading. The Copilot panel's
  collapsed "Saved explanation (no longer in the conversation)" copy is gone; the panel shows the
  live conversation only.
- **Sidebar footer**: a horizontal separator (`panel-resizer--session-footer`, pointer or ArrowUp/
  ArrowDown/Home/End) above the footer sets its height (88–640px, remembered in
  `gosu.model-lab.session-footer-height.v1`); the footer scrolls inside that height and the model
  tree keeps the rest. "Graph import status" and "Model builder LLM" fold to one line each
  (`<details>`, remembered in `gosu.model-lab.session-sections.v1`; the status opens itself when an
  import starts; the builder line shows the chosen model and reasoning). The import button is a
  30px pill beside its note instead of a full-width bar.

Regression tests: `module-detail-flow.test.ts` (mark: filled tag and ring; the explanation box holds
the saved answer ahead of "At a glance", no panel copy), `model-graph.test.ts` (+1: footer height
from pointer and keys, stored height and sections, grid rows, separator, scrolling footer, pill
button).

## Briefing Lab weather: the hour under the cursor

User request: show the hour's temperature and precipitation probability when the cursor is on the
chart's vertical line, not only exactly on a temperature dot.

A transparent hit layer over the plot maps the pointer x to the nearest hour (`nearestHourIndex`),
draws a dashed guide with a label ("09시 · 20°C · 강수 40%") and fills the footnote as before; leaving
the chart clears it. Dots and bars keep their focus and click handling. Test: `weather-card.test.tsx`
(+1).
