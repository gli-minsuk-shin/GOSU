## Research Notes works again, and stops forking a project's folder

User report: "연구 노트 접근이 아예 안되는데? Obsidian folder 에 접근 허용이 안됨."

This is a regression 0.58.147 caused, sitting on top of an older defect that had already split the
user's notes in two. Both are fixed here.

### What went wrong

- 0.58.147 changed a vault's id from a hash of _path + device + inode_ to a hash of the path alone,
  so that a grant would survive macOS moving the inode. It taught exactly one function,
  `matchesGrant`, to also accept the old id — and left more than a dozen other comparisons strict.
  Every stored link, every folder marker and `requireGrant` itself still held the old id, so after
  0.58.147 GOSU treated every project as belonging to a different vault: the screen reported the
  grant as active while every read behind it failed with `vault_grant_stale`, and the Authorize
  button stayed disabled because the workspace could not be read at all.
- The older defect: whenever the vault's device and inode changed on their own, GOSU did not
  recognize the project's existing folder and created `<name>--<project id>` beside it. Evidence in
  the user's own vault: three folders created on 2026-09-21 and 2026-09-22, each carrying the
  vault's then-current inode hash, beside six folders carrying an earlier one. For one project the
  newer folder holds a 46,801-byte Literature Review while the older one holds 1,587 bytes, so the
  user's recent work went into the copy GOSU had just forked off.

### The rule this release uses instead

A folder found inside the vault that is open is in that vault, whatever id its marker recorded. The
id was the vault's identity at the time, and that identity has moved on its own more than once.
Location is the stronger fact, so the marker is matched on `projectId` and not on `vaultId`.

- `ensureProject` adopts: a stored link whose folder still claims this project has its id rewritten
  once, and the folder's marker with it, so every later comparison is exact.
- When the wanted folder name is taken by something that is not this project, GOSU now looks for a
  folder this project already owns under another name before adding a second one.
- `requireGrant` and `requireVault` accept an id written under a previous identity of the same
  vault, which is the one question `matchesGrant` answers. They disagreed before, and that
  disagreement is what made the screen and the reads tell the user different things.

### When two folders claim one project

GOSU does not guess. It refuses with `research_notes_folder_ambiguous`, names nothing it has
changed, and tells the user to keep the folder they want and move or rename the other. Picking
either one silently would hide the other behind it, and in this user's vault one of the two is where
the recent literature work actually is.

The duplicate folders already in a vault are not touched by this release. They are the user's files
and which copy to keep is the user's decision; GOSU now reports them instead of writing into one.
