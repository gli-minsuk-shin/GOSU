## Generation progress beside the page title

User request: even collapsed, the Briefing progress box takes a lot of space; move it next to the
"개인 연구 브리핑" title.

Cause: the progress disclosure rendered inside the generation controls, as a second row under the
interval select and buttons, and the controls column reserved 420px whenever the controls existed,
so the header grew by a row while a run was active.

Change:

- The Briefing header puts the title in `.briefing-title-row` with an empty `.briefing-title-progress`
  slot (history tab, personal routine). `BriefingGenerationControls` takes `progressSlot` and renders
  the running `BriefingGenerationProgress` there through a portal; without a slot it stays inline as
  before. Polling, state and the job alerts are unchanged.
- In the title row the collapsed box is one line (max 360px, text ellipsized); the opened detail is
  an absolutely positioned panel under it (z-index above the page, shadow), so opening it does not
  move the briefing content.
- The controls reserve the 420px column only while a progress box or an alert is inside them;
  otherwise the buttons keep their natural width and the title column takes the rest.

Checked visually with the real `styles.css` and `workspace.css` in a static page rendering the real
progress component at 1100px: collapsed, the title, progress summary ("AI 요약 · 이메일 · 6/28개 저장 ·
경과 1분 35초") and buttons share one header row; opened, the detail floats over the content. The
first attempt wrapped the box under the title because of the reserved column, which the third change
fixed.

Measured again at several widths (same static page, element rectangles read in the browser): with
the Briefing main panel 1880, 1240, 1100, 940 and 820px wide, the header is 48px and the title,
progress summary and buttons share one row (the opened detail is `position: absolute` and the
content starts right under the header). At 600px the buttons wrap to a second row (88px), the same
height a running header had before this change at every width. A completed run with an alert keeps
the previous 88px layout.
